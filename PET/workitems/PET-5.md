Экран графиков динамики питомца и обеспечение того, что режим `dataSource=local` и перенос local → network не отстают от новой событийной модели. Целевое поведение — страницы «Графики динамики — Frontend» и «Графики динамики — Frontend (dataSource=local)».

Зависит от PET-3 (эндпоинт агрегации) и PET-4 (типы, иконки, подписи).

## Состав работы

* Экран динамики: выбор питомца, метрики и периода (неделя/месяц/год → интервал day/week/month); список доступных метрик строится из реестра метрик, а не задаётся списком на экране.
* Форма графика выбирается по `value_kind`: линия для измерений, столбцы для количеств, столбцы по категориям для категориальных наблюдений. Ось Y подписывается единицей из реестра; ряды с разными единицами не смешиваются на одной оси.
* Пустые интервалы отображаются как отсутствие данных и не интерполируются линией через пропуск.
* Выбор библиотеки построения графиков — часть этой задачи: в проекте её сейчас нет, есть только `react-native-svg`. Требование к выбору — работа на iOS и Android без нативных модулей вне текущего набора зависимостей.
* Кэш React Query по ключу рядов; инвалидация после добавления, редактирования и удаления события того же питомца — общая фабрика ключей с активностями календаря.
* Локальный режим: агрегация из локальной коллекции событий тем же общим кодом свёртки, что и разбор ответа сервера, — расхождение цифр между режимами недопустимо.
* Перенос local → network: события с типизированным значением переносятся без потерь, `POST /import/local-data` принимает ту же форму значения (проверить на всех 14 типах).

## Готово, когда

* График строится для каждого агрегируемого типа события в обоих режимах, и на одинаковых данных `network` и `local` дают одинаковые ряды.
* Тип `other` не предлагается в списке метрик.
* Перенос локального аккаунта с событиями всех типов не теряет ни одного поля значения.
