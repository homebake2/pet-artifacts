Требует PET-183 (миграция БД, добавляющая pet.user_id).

Сейчас `authProfile()` (handlers/ownership.go) на каждом pet/event-запросе ищет строку `profile` по `user_id` и возвращает 404 "Профиль не найден", если её нет — из-за этого доступ к трекеру блокирован до заполнения профиля. Нужно:

1. Заменить `authProfile()` на аналог, который берёт `userID` напрямую из токена, без похода в таблицу `profile` и без 404 в случае её отсутствия.
2. В handlers/pet.go заменить все запросы `... WHERE profile_id = $1 ...` (список, создание, карточка, обновление, удаление, `pet_idempotency_key`) на `... WHERE user_id = $1 ...`.
3. В handlers/events.go заменить проверки владения питомцем через `profile_id` на проверку через `pet.user_id` (событие принадлежит пользователю, если принадлежащий ему питомец найден по `user_id`) — во всех эндпоинтах: `POST /events`, `PATCH /events/{id}`, `DELETE /events/{id}`, `GET /events/{id}`, `GET /activities`, `GET /pet/{id}/events`.
4. Эндпоинты `/profile` (`GET`/`POST`/`PUT`) не трогать — их поведение (включая штатный 404 на `GET /profile` при отсутствии профиля) не меняется.
5. Единая политика 404 для "не существует/чужое/мягко удалено" (см. «Общие требования: IDOR и владение ресурсами») сохраняется без изменений — меняется только столбец проверки владения.

Требования по каждому эндпоинту обновлены на соответствующих страницах (см. `pages` этой задачи) — прежние формулировки про "профиль" и "profileID" в предусловиях/сценариях/ошибках заменены на "пользователь"/"userID". Frontend изменений не требует.

**Выполнено:** `authProfile()` удалена (её вызовы заменены на прямой `requireUserID()`), `database/pet.go` и `handlers/{pet,events}.go` переведены на `user_id`/`CheckPetBelongsToUser`/`GetPetByIDAndUserID` и т.п. Пункт 2 про `pet_idempotency_key` не применялся — этой таблицы в коде ещё нет (см. примечание в PET-183). `/profile` не тронут. Добавлен интеграционный тест `TestPetAndEventLifecycle_WithoutProfile`, проверяющий создание питомца и события без заполненного профиля.
