После входа через `POST /auth/guest` (создаётся запись в `users`, но не в `profile`) запрос `GET /pet` с валидным access-токеном отвечает `500 INTERNAL_ERROR` вместо документированного `404` (см. «Список питомцев — Backend», раздел «Обработка ошибок»: 404 должен возвращаться, если профиль не найден для авторизованного пользователя).

Воспроизведение:

```
curl 'https://pet-app-dk8u.onrender.com/auth/guest' \
  -H 'Content-Type: application/json' \
  --data-raw '{"device_id":"<device_id>"}'
# -> получить access_token из ответа

curl 'https://pet-app-dk8u.onrender.com/pet' \
  -H 'Authorization: Bearer <access_token>'
# -> 500 INTERNAL_ERROR вместо ожидаемого 404
```

Причина: `authProfile` в `handlers/ownership.go` при ошибке `database.GetProfileIDByUserID` всегда пишет `500 INTERNAL_ERROR`, не различая `sql.ErrNoRows` (профиль не найден — должен быть `404`) и реальные ошибки БД (`500`). Поскольку `authProfile` используется всеми хендлерами питомцев (list/create/update/delete), баг затрагивает не только `GET /pet`.

Нужно исправить `authProfile`, чтобы при `sql.ErrNoRows` (профиль не найден) возвращался `404`, как это уже сделано, например, в `resolveOwnedPet`.
