При создании питомца прямо с экрана добавления события (сценарий из PET-131: у гостя нет ни одного питомца) форма после возврата предзаполняет поле "Питомец" неверным id — при отправке `POST /events` уходит `pet_id`, который не совпадает с id, реально возвращённым `POST /pet` (и который затем отдаёт `GET`).

Пример:

- `POST /pet` создаёт питомца, `GET` по нему отдаёт id `98434533-94e9-4621-bff8-9c4529b41965`.
- Последующий `POST /events` уходит с `pet_id: "5aeca043-4ff0-4bd3-a56b-d8b30b1425ed"` — другим значением.

Похоже, форма предзаполняется из устаревшего локального состояния/кэша (созданного до успешного ответа сервера, либо не инвалидированного после создания питомца), а не из реального id, пришедшего в ответе `POST /pet`. Нужно найти во фронтенде место, где id нового питомца передаётся обратно в форму добавления события после его создания, и убедиться, что используется id из серверного ответа (а не локально сгенерированный/устаревший), либо что кэш списка питомцев инвалидируется и форма берёт id из актуальных данных.

Куда смотреть: обработчик успешного создания питомца на экране создания (открытом из формы добавления события, см. PET-131) и то, как он передаёт petId обратно при навигации назад.
