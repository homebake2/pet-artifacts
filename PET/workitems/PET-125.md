Валидация value на бэкенде сейчас единая для всех типов события (строка не более 50 символов) и не учитывает тип события. Нужна per-type валидация с конкретным форматом на каждый type: weight — строка с десятичным числом (напр. "4.5"), сервер парсит через strconv.ParseFloat, диапазон 0.01–200 (кг), единица измерения фиксирована и в строке не хранится; urine/defecation/vomit/diarrhea — value не число, а один из двух статусов {"normal","abnormal"}, остальное несёт notes; other — произвольный текст 1–50 символов, не пустой. value хранится в БД как text во всех случаях. Схема согласована с Zod-схемой на FE (см. PET-124). Подробности и таблица — на странице "Добавление события — Backend".
