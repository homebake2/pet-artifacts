Проблема: в коде есть три похожих эндпоинта чтения событий питомца: GET /events/{id} (одно событие по id), GET /activities (список за диапазон дат, сгруппированный по дням), GET /pet/{id}/events (GetPetEventsHandler, все события без фильтра по датам, без группировки, с корректным 404 для чужого питомца). Третий не входит в описанные продуктовые подсценарии и не используется ни одним известным экраном фронтенда.
Решение (принято): эндпоинт не удаляется — оставить как есть и явно задокументировать в OpenAPI и в комментарии у GetPetEventsHandler его назначение: плоский список всех событий питомца без пагинации/фильтра по датам, задел на будущий сценарий (например, «вся история питомца» без разбивки по дням). Явно пометить в документации, что на момент написания клиентом не используется.
Затронутые файлы: handlers/events.go, open-api/spec.json.
