Требования к удалению события описывают мягкое удаление через event.deleted_at, но в модели данных event такого поля пока нет — миграция не выполнена. Требуемая миграция: ALTER TABLE event ADD COLUMN deleted_at timestamptz NULL (nullable, без default; NULL = не удалено, timestamp в UTC = момент удаления). После миграции фильтр deleted_at IS NULL обязателен во всех трёх эндпоинтах чтения событий: GET /activities, GET /events/{id}, GET /pet/{id}/events. Эта задача — основа для корректной работы IDOR-проверок и soft-delete событий, описанных в требованиях к редактированию и просмотру событий. Подробности — на странице "Удаление события — Backend".
