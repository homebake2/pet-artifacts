POST /events не поддерживает idempotency key, поэтому повторная отправка запроса при обрыве соединения может создать дублирующееся событие. Нужен опциональный заголовок Idempotency-Key (UUID v4). Хранение: столбец event.idempotency_key (nullable text) с частичным уникальным индексом CREATE UNIQUE INDEX event_pet_idempotency_key_idx ON event (pet_id, idempotency_key) WHERE idempotency_key IS NOT NULL. Алгоритм: если заголовок передан — перед вставкой SELECT по (pet_id, idempotency_key); если строка найдена, вернуть её как 201 с тем же телом без вставки; если не найдена — вставить, а гонку параллельных запросов (нарушение уникального индекса) трактовать не как 500, а повторить SELECT и вернуть найденную строку. Окно дедупликации не ограничено по времени, пока событие не удалено физически. Подробности — на странице "Добавление события — Backend".
