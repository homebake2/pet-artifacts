## Назначение

Сервис не хранит персональные данные дольше, чем они нужны. Для каждой категории данных на сервере задан срок хранения и правило, по которому данные удаляются без участия пользователя. Эти сроки публично описаны в политике конфиденциальности и должны совпадать с ней.

## Сроки хранения

| Данные | Срок хранения | Что происходит по истечении |
| --- | --- | --- |
| Аккаунт, профиль, питомцы, события, записи Ветпаспорта | Пока существует аккаунт | Удаляются физически при удалении аккаунта (см. [Общие требования: Soft-delete](obschie-trebovaniya-soft-delete.md), раздел «Исключения») |
| Мягко удалённые питомцы, события и записи пяти сущностей Ветпаспорта | 90 суток с момента удаления | Физически удаляются вместе со связями и файлами |
| Файлы (строки и объекты в хранилище), у которых больше нет владельца | До ближайшей очистки | Удаляются; объект в хранилище удаляется, когда на него не осталось ссылок |
| Загрузки файлов, не подтверждённые клиентом | 24 часа с момента создания | Строка файла и объект в хранилище удаляются |
| Счётчики регистраций по IP-адресу (`registration_rate_limit`) | День попытки и предыдущие сутки, не дольше 2 суток | Строки удаляются |
| Счётчики неудачных попыток входа по логину и IP (`login_rate_limit`) | До конца окна подсчёта и ещё 24 часа | Строки удаляются |
| Предложения с сайта | 24 месяца с момента отправки | Удаляются; также удаляются сразу при удалении аккаунта, uuid которого указан в предложении |

Сроки хранятся на сервере как именованные константы, а не в базе данных и не в конфигурации приложения: изменение срока — изменение требований и политики.

## Правила очистки

* Очистка выполняется на сервере автоматически: при старте сервиса и затем регулярно (не реже раза в час). Пользователь и клиентские приложения для неё ничего не делают.

* Очистка не должна менять поведение API: срок хранения наступает только для данных, которые API уже не показывает (мягко удалённые записи, записи без владельца, истёкшие счётчики). Окончание срока никогда не затрагивает активные данные.

* Очистка выполняется порциями ограниченного размера, чтобы не блокировать таблицы надолго; необработанный остаток удаляется при следующем проходе.

* Сбой очистки не влияет на обработку запросов: ошибка фиксируется в журнале и мониторинге, следующий проход повторяет попытку.

* Физическое удаление питомца вместе с ним удаляет его связи с событиями и записи Ветпаспорта. Событие, у которого после этого не осталось ни одного питомца, удаляется целиком; событие, привязанное и к другим питомцам, остаётся у них.

* Удаление объекта из хранилища выполняется после фиксации изменений в базе данных и допускает сбой (объект без строки файла не виден пользователю). Объект удаляется, только если на него не ссылается ни одна строка файла: ссылочные строки файлов делят один объект.

## Что не входит в сроки

* Данные, которые удаляет сам пользователь: удаление питомца, события и записи Ветпаспорта запускает отсчёт 90 суток; удаление аккаунта удаляет данные сразу.

* Резервные копии базы данных и журналы хостинга: их хранение определяют поставщики инфраструктуры; в политике конфиденциальности сказано, что копии и журналы могут сохраняться у них ограниченное время.

* История передач питомцев и приглашений к доступу хранится с обнулёнными ссылками на удалённые аккаунты и содержит только кличку и вид питомца (см. [Общие требования: Soft-delete](obschie-trebovaniya-soft-delete.md)); отдельный срок для неё не задан.

## Известный пробел в реализации

* Не заданы сроки для неактивных гостевых аккаунтов и для уведомлений о потере доступа к питомцу (`pet_access_notice`), которые не были закрыты пользователем.
