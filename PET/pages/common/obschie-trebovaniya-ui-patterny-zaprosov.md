## Скелетоны при загрузке

Любой блок экрана, который получает данные GET-запросом, обязан на время ожидания ответа отображать скелетон (skeleton), повторяющий структуру итогового контента, — а не пустое место или голый спиннер. Правило действует по умолчанию на всех экранах; конкретный сценарий переопределяет его только если явно указывает иное на своей странице.

## Пустые состояния

Если успешный GET-запрос вернул пустые данные или пустой список, блок обязан отображать пустое состояние (empty state) с понятным сообщением вместо пустого места или списка без пояснения. Правило действует по умолчанию на всех экранах; конкретный сценарий переопределяет его только если явно указывает иное на своей странице.

## Блокировка повторной отправки

Любая кнопка, инициирующая мутирующий запрос (создание/изменение/удаление, логин, логаут и т.п.), обязана на время выполнения запроса явно переходить в состояние загрузки: становиться disabled и показывать индикатор загрузки (спиннер на кнопке или аналогичную визуальную индикацию) вместо/поверх своего обычного содержимого. Это предотвращает двойную отправку по повторному тапу и связанные с ней гонки на бэкенде. Правило действует по умолчанию на всех экранах — отдельные страницы сценариев не обязаны его переописывать, только ссылаться сюда.

Исключение — Logout: кнопка «Выйти» показывает индикатор загрузки только на момент отправки запроса, после чего фронтенд немедленно очищает локальное состояние и переходит на экран входа, не дожидаясь и не обрабатывая результат сетевого запроса (см. страницу «Logout — Frontend»).

## Таймауты сетевых запросов

Каждый сетевой запрос имеет таймаут, по истечении которого клиент трактует его как сетевую ошибку (а не оставляет экран/кнопку в состоянии загрузки бесконечно). Рекомендуемые значения по умолчанию: 10 секунд для обычных GET/POST/PUT/DELETE, 5 секунд для операций внутри цепочки авто-refresh токена (см. «Общие требования: Сессия, 401 и авто-refresh токена»). Конкретный сценарий может переопределить значение, если у него есть особые причины — тогда это указывается явно на его странице.

## Обработка неудачного GET-запроса (загрузка данных)

Если запрос на получение данных для экрана/блока экрана завершился ошибкой (сеть, 5xx, таймаут), экран/блок показывает состояние «не удалось загрузить данные» с кнопкой «Повторить». Правила:

* Кнопка «Повторить» перезапускает только тот запрос (или группу запросов), который реально упал — если на экране несколько независимых блоков данных (например, карточка сущности + список связанных с ней записей), успешно загруженные блоки не должны становиться недоступны или перезагружаться из-за ошибки в другом блоке.

* 401 — не обрабатывается как обычная ошибка загрузки (без кнопки «Повторить» в общем error-state) — вместо этого срабатывает авто-refresh токена, см. «Общие требования: Сессия, 401 и авто-refresh токена».
