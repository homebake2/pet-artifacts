## Правило

Мобильное приложение сообщает бэкенду свою версию в каждом сетевом запросе к API (включая вход, обновление токена и запрос баннеров) заголовком:

```
X-App-Version: <MAJOR.MINOR.PATCH>
```

Значение — версия приложения в формате `MAJOR.MINOR.PATCH` (та же, что передаётся в параметре `appVersion` запроса баннеров). Если версию определить не удалось или она не в этом формате, заголовок не отправляется.

Заголовок не требует авторизации и описан в OpenAPI как необязательный параметр `AppVersion` (`components.parameters`), подключённый на уровне каждого пути: его отсутствие или некорректное значение никогда не приводит к ошибке и не меняет ответ.

Запросы не к API (например, загрузка файла по presigned-ссылке в хранилище) заголовок не получают.

## Использование на backend

Версия нужна только для диагностики: backend пишет её в строку лога каждого запроса и ставит тегом `app_version` в события Sentry, чтобы ошибки можно было разбирать в разрезе версий приложения. Значение, не соответствующее формату `MAJOR.MINOR.PATCH`, отбрасывается (в лог и тег не попадает).

Решения о показе баннеров по версии принимаются по параметру `appVersion` запроса баннеров (правило таргетинга `app_version`), а не по этому заголовку.
