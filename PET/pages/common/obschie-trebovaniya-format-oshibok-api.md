## Единый формат тела ошибки

Любой ответ backend с кодом ошибки (4xx/5xx) возвращает тело единого формата (конкретные имена полей могут отличаться при реализации, но состав и смысл — нет):

* **errorCode** — короткий буквенный код из фиксированного enum (например `VALIDATION_ERROR`, `UNAUTHORIZED`, `NOT_FOUND`, `FORBIDDEN`, `INTERNAL_ERROR`) — на него ориентируется клиентская логика (retry, редирект на логин и т.п.), а не на HTTP-статус или текст сообщения;

* **message** — человекочитаемое сообщение для отладки/логов;

* **payload** — произвольные дополнительные данные об ошибке (например, какое поле не прошло валидацию), тип `any`, опционально.

## Локализация ошибок

Клиент не показывает пользователю сырой `message` с сервера напрямую — сообщения на экране формируются на клиенте по `errorCode` через локализацию приложения (i18next, en/ru), независимо от языка, на котором backend сформировал текст.

_Текущее ограничение (временно принято): backend на данный момент возвращает _`message`_ захардкоженным на русском языке. Локализация самого backend (i18n на стороне сервера) не прорабатывается в рамках текущей итерации — заведена как отдельная задача на будущее. До её реализации это не блокирует локализацию клиента, так как клиент ориентируется на _`errorCode`_, а не на _`message`_._
