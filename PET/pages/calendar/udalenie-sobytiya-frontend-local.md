## Назначение

Определяет, как система удаляет событие, когда активен режим `dataSource=local`.

## Алгоритм удаления

1. Клиент проверяет, что событие с указанным `id` существует, принадлежит текущему аккаунту и ещё не помечено удалённым. Если событие уже помечено удалённым (гонка — например, удалено с этого же устройства из другого места UI) — клиент трактует это как «уже удалено» и тихо убирает событие из UI, без сообщения об ошибке — по тому же правилу, что действует для сетевого режима (см. [Общие требования: Soft-delete](../common/obschie-trebovaniya-soft-delete.md), раздел «UX при гонках удаления»).

2. Кнопка подтверждения удаления переходит в состояние загрузки и блокируется на время операции, чтобы исключить повторный тап (см. [Общие требования: UI-паттерны запросов](../common/obschie-trebovaniya-ui-patterny-zaprosov.md)).

3. Клиент помечает событие мягко удалённым (проставляет `deletedAt`), не удаляя запись физически — по общему правилу soft-delete (см. [Локальный режим (dataSource=local) — общая архитектура хранения](../common/lokalnyi-rezhim-datasource-local-zaglushka.md), раздел «Мягкое удаление»). Клиент дожидается подтверждения записи, после чего событие немедленно перестаёт быть видимым в календаре и на карточке питомца.

## Обработка ошибок

| Условие | Что делает клиент |
| --- | --- |
| Событие с данным `id` не найдено или принадлежит другому аккаунту | Показывается сообщение «событие не найдено» |
| Событие уже мягко удалено (гонка) | Тихо убирается из UI без сообщения об ошибке |
| Ошибка записи в локальное хранилище | Показывается сообщение об ошибке удаления; событие остаётся видимым в UI |
