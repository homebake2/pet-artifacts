## Назначение

Промежуточный экран между карточкой факта или напоминания и их изменением. Он показывает запись целиком (данные, питомцев, файлы, расписание и источник напоминания) и является точкой, из которой запускаются изменение, удаление и отметка записи (удаление дополнительно доступно из списка, см. «Удаление из списка»). Одним экраном с одной структурой обслуживаются два вида записи: **факт** (запись «Уже произошло») и **напоминание** (один момент расписания). Сам экран данные не редактирует: все изменения выполняются существующими формами и подтверждениями, на которые он ведёт.

## Действующие лица и предусловия

* Авторизованный пользователь с любой ролью у питомца записи (`owner`, `full`, `view`); набор доступных действий определяется ролью (см. «Бизнес-правила и валидация»).

* Запись подтверждена сервером (в сетевом режиме у неё есть серверный `id`): неподтверждённую запись из списка открыть нельзя (см. [Общие требования: Оптимистичные обновления (dataSource=network)](../common/obschie-trebovaniya-optimistichnye-obnovleniya.md), раздел «Визуальная индикация фоновой синхронизации»).

## Точки входа

Экран открывается нажатием на карточку записи; вид записи (факт или напоминание) определяется карточкой. Карточка больше не ведёт напрямую в форму редактирования, в отметку или в выбор «Что изменить?».

1. Список дня экрана «Календарь» — факты и напоминания.

2. Превью событий на карточке питомца — только факты.

3. Экран «События питомца» — только факты.

Из точек входа 2 и 3 экран получает питомца, в контексте которого он открыт (для варианта «Убрать только у {питомец}», см. «Удаление факта»); из календаря контекстного питомца нет. Напоминания в точках входа 2 и 3 не показываются (см. [Напоминания — Frontend](napominaniya-frontend.md), «Хранение состояния и побочные эффекты»).

## Содержимое экрана

Заголовок экрана и навигация зависят от вида записи («Событие» либо «Напоминание»). Всегда имеется возможность вернуться назад.

### Общие блоки

* **Тип и значение.** Тип показывается обозначением и подписью из единого справочника типов (так же, как на карточке, см. [Просмотр календаря — Frontend](prosmotr-kalendarya-frontend.md)); значение — строкой, собранной по форме `value` типа, с единицей измерения (см. [Модель значения события и реестр метрик](../common/model-znacheniya-sobytiya-i-metriki.md)). Если у типа нет значения, блок значения не показывается. Для `vaccination` показывается название вакцины и, у дополнительного напоминания вакцинации, момент вакцинации; для `other` — текстовая метка.

* **Питомцы.** До 3 питомцев перечисляются в строке. От 4 питомцев показывается компактное представление с общим числом; имеется возможность открыть полный список питомцев записи и из него открыть карточку питомца. Для записи с одним питомцем показывается его имя.

* **Автор.** Показывается только если питомцем пользуются несколько человек: «Вы» либо имя автора (см. [Общие требования: Доступ к питомцу](../common/obschie-trebovaniya-dostup-k-pitomtsu.md)).

* **Заметка.** Показывается, только если непуста.

* **Файлы.** Блок показывается, только если у записи есть файлы, с их числом. Фотографии показываются крупными миниатюрами, документы — именем файла (`filename`) или подписью «Документ», если имя пусто. Имеется возможность открыть любой файл (см. «Просмотр файла»).

### Факт

Дополнительно к общим блокам: **дата и время** факта (формат локали интерфейса, часовой пояс устройства). Источник данных — `GET /events/{id}` (поля `files`, `pets`, `author`, см. [Файлы события — Backend](fayly-sobytiya-backend.md)).

### Напоминание

Источник данных — `GET /reminders/{id}` (см. [Напоминания — Backend](napominaniya-backend.md), эндпоинт E). Дополнительно к общим блокам:

* **Момент напоминания** — дата и время (`remind_at`). Для будущего напоминания рядом показывается, через сколько оно наступит; для наступившего — признак «Нужна отметка».

* **Расписание.** Для разового напоминания («Один раз») показывается только частота. Для повторяющегося — частота (для «Определённых дней недели» с перечнем дней, для «Через каждые N дней» с интервалом), времена суток, период (дата начала и дата окончания либо «без окончания») и сколько напоминаний осталось (число незавершённых напоминаний серии, `plan_unclosed_count`, включая это; при заданной дате окончания она показывается рядом).

* **Источник.** Для напоминаний со связанными настройками (`plan_source` ≠ `manual`: лекарство, вакцинация, дополнительное напоминание вакцинации) показывается блок с видом источника и названием записи Ветпаспорта (`plan_source_title`). Имеется возможность открыть соответствующий раздел Ветпаспорта питомца. У дополнительного напоминания вакцинации в значении показывается момент вакцинации.

* **Файлы.** Если у напоминания есть и файлы настроек (`plan_files`), и собственные файлы (`files`), они показываются двумя различимыми блоками: файлы настроек (общие для серии) и файлы этого напоминания. Пустой блок не показывается.

* **Отметка.** Если момент напоминания наступил (`remind_at` ≤ текущий момент устройства), показывается выделенный блок «Вы выполнили это?» с возможностью отметить «Выполнено» или «Не выполнено». У будущего напоминания блока нет: отметить его нельзя.

Данные записи на экране только отображаются; значение и заметка связанных напоминаний не редактируются здесь и не редактируются в формах напоминания (меняются в записи Ветпаспорта, см. [Напоминания — Frontend](napominaniya-frontend.md), «Связанные напоминания»).

## Основной сценарий

### A. Открытие и загрузка

1. Пользователь нажимает на карточку записи. Система открывает экран и запрашивает данные записи: факт — `GET /events/{id}`, напоминание — `GET /reminders/{id}`. Для напоминания дополнительных запросов за расписанием и источником нет: они приходят в ответе.

2. Пока запрос выполняется, экран показывает скелетон, повторяющий структуру содержимого соответствующего вида записи (см. [Общие требования: UI-паттерны запросов](../common/obschie-trebovaniya-ui-patterny-zaprosov.md), «Скелетоны при загрузке»); возможность вернуться назад доступна, действий над записью нет.

3. После ответа экран показывает содержимое и действия, доступные по роли и виду записи.

### B. Действия над фактом

1. **Редактирование.** Имеется возможность открыть форму редактирования факта (см. [Редактирование события — Frontend](redaktirovanie-sobytiya-frontend.md)). После успешного сохранения пользователь возвращается на этот же экран с обновлёнными данными (см. «Возврат после изменения»).

2. **Удаление.** Имеется возможность удалить факт; удаление всегда начинается с диалога подтверждения «Удалить событие?» (см. [Удаление события — Frontend](udalenie-sobytiya-frontend.md)).

   * Если у факта несколько видимых питомцев, диалог перечисляет питомцев, у которых запись будет удалена, и предлагает «Удалить у всех». Если экран открыт в контексте питомца (точки входа 2 и 3), дополнительно предлагается «Убрать только у {питомец}» (отвязка питомца без удаления записи у остальных, `PATCH /events/{id}` с `pet_ids` без этого питомца). Из календаря вариант отвязки не предлагается.
   * При удалении факта действует окно отмены 5 секунд (мягкое удаление; запись исчезает из списков сразу, пользователь может отменить удаление).
   * После подтверждения экран закрывается, пользователь возвращается на экран, с которого был открыт экран записи; там показывается сообщение об удалении с возможностью отмены. После варианта «Убрать только у {питомец}» экран закрывается так же, окна отмены у отвязки нет.

### C. Действия над напоминанием

1. **Изменение.** Имеется возможность изменить напоминание; действие запускает сценарий «Открытие напоминания» из [Напоминания — Frontend](napominaniya-frontend.md), раздел B, без изменения его правил:

   * если у настроек несколько незавершённых напоминаний и источник не вакцинация — выбор «Что изменить?» («Только это напоминание» / «Все напоминания» / «Отмена»);
   * иначе сразу открывается форма «Все напоминания» (одноэкранная форма настроек и расписания);
   * для напоминаний вакцинации (напоминание на следующую вакцинацию и дополнительное) вариант «Только это напоминание» не предлагается; действие называется по тому, что изменяется, — расписание, и сразу открывает форму расписания.

   У наступившего напоминания (требующего отметки) действия изменения нет: доступны только отметка и удаление.

2. **Отметка наступившего напоминания.** Имеется возможность отметить напоминание «Выполнено» или «Не выполнено» (см. [Напоминания — Frontend](napominaniya-frontend.md), раздел E).

   * «Выполнено» создаёт факт с данными напоминания, «Не выполнено» закрывает напоминание без факта; в обоих случаях напоминание закрывается, экран закрывается и пользователь возвращается на экран, с которого он был открыт.
   * Если отмечено «Выполнено» напоминание на следующую вакцинацию (`plan_source = vaccination`), сразу при отметке показывается вопрос «Вакцинация выполнена. Указать дату следующей вакцинации?» («Да» / «Нет»): «Нет» закрывает вопрос и экран; «Да» открывает форму создания вакцинации того же питомца с предзаполненными данными (см. [Вакцинации — Frontend](../vetpassport/vaktsinatsii-frontend.md)), экран записи при этом закрывается и возврат из формы ведёт на экран, с которого он был открыт. Для «Не выполнено» и для дополнительного напоминания вакцинации вопрос не задаётся.

3. **Удаление.** Имеется возможность удалить напоминание. Сначала показывается подтверждение «Удаление необратимо» («Удалить» / «Отмена»; для нескольких питомцев сообщение перечисляет всех питомцев). Окна отмены нет: удаление жёсткое. Если у настроек несколько незавершённых напоминаний, после подтверждения предлагается выбор «Что удалить?» («Только это напоминание» / «Все напоминания» / «Отмена»); для связанных настроек выбор сообщает, что запись Ветпаспорта «{название}» останется. После удаления экран закрывается и пользователь возвращается на экран, с которого он был открыт.

4. **Переход к записи Ветпаспорта.** У связанного напоминания имеется возможность открыть раздел Ветпаспорта («Лекарства» либо «Вакцинации») соответствующего питомца (без перехода к конкретной записи). Возврат из него ведёт на экран записи.

### Удаление из списка

Карточку факта или напоминания можно удалить прямо из списка (список дня, превью событий и «События питомца» для фактов) без открытия экрана записи. Удаление запускает те же подтверждения и выбор, что и удаление с экрана записи (разделы B.2 и C.3), с теми же правилами окна отмены и контекстного питомца; после подтверждения запись исчезает из списка.

### D. Просмотр файла

1. Имеется возможность открыть файл из блока файлов. Просмотр доступен любой роли.

2. **Фотография** открывается на весь экран: имеется возможность листать все фотографии записи (отображается номер текущей из общего числа), увеличивать фотографию и закрыть просмотр (в том числе смахиванием вниз), а на iOS — также поделиться файлом средствами ОС (на Android возможности поделиться нет). Для напоминания в просмотр входят фотографии и файлов настроек, и собственных файлов напоминания.

3. **Документ** (PDF) открывается средствами ОС: система предлагает открыть его в просмотрщике либо подходящем приложении на устройстве.

4. После закрытия просмотра пользователь остаётся на экране записи.

### E. Возврат после изменения

После успешного сохранения изменения из формы:

* Если открытая запись продолжает существовать (изменение факта; изменение напоминания без пересоздания напоминаний: тип, значение, заметка, питомцы, файлы настроек), пользователь возвращается на экран записи, который показывает обновлённые данные и сообщение об успешном сохранении.

* Если изменено расписание («Все напоминания»), будущие напоминания серии пересоздаются под новыми идентификаторами, но экран записи не закрывается: клиент передаёт в `PATCH /reminder-plans/{id}` идентификатор открытого напоминания (`reminder_id`), а сервер в ответе возвращает идентификатор напоминания, которое теперь его представляет (тот же, если напоминание сохранилось, например наступившее; иначе — созданное на тот же момент, а если такого момента в новом расписании нет, — первое из созданных; см. [Напоминания — Backend](napominaniya-backend.md), эндпоинт C). Как только сервер подтвердил изменение, экран переключается на возвращённое напоминание и показывает его данные; до подтверждения показывается напоминание с оптимистично пропатченным расписанием. Если сервер не вернул идентификатор (напоминание закрыто или удалено), экран показывает состояние «Напоминание не найдено».

* Если исходное напоминание заменено новой записью (изменение через «Только это напоминание», включая случай, когда изменились только собственные файлы: исходное напоминание закрывается, вместо него создаётся новое напоминание либо факт), экран записи не закрывается, а переключается на новую запись: на новое напоминание либо на факт («Уже произошло»). Идентификатор новой записи клиент берёт из ответа `POST /reminders/{id}/detach` (`plan` — для напоминания, `event` — для факта). Пока сервер не подтвердил замену, экран показывает исходное напоминание с индикацией «синхронизируется»; после подтверждения переключается, сообщение об успешном сохранении показывается на экране записи. Если замена не подтверждена и операция в состоянии «требует внимания», экран остаётся на исходном напоминании.

## Бизнес-правила и валидация

* Набор действий определяется ролью у питомцев записи (поле `access`, см. [Общие требования: Доступ к питомцу](../common/obschie-trebovaniya-dostup-k-pitomtsu.md)): `owner` и `full` — изменение, удаление и (у наступившего напоминания) отметка; `view` — экран только отображает данные, действий нет, и экран явно показывает, что он открыт в режиме просмотра. Запись с несколькими питомцами изменяема только если роль `owner`/`full` у каждого её питомца, иначе она показывается без действий. Просмотр файлов доступен любой роли.

* Запись с неподтверждённой операцией (создание, изменение), в том числе в состоянии «требует внимания», из списков не открывается. Если пользователь вернулся на экран после изменения (раздел E), а сервер ещё не подтвердил его, экран показывает уже новые данные с индикацией «синхронизируется» либо «требует внимания», а действия над записью недоступны, пока операция не подтверждена (см. [Общие требования: Оптимистичные обновления (dataSource=network)](../common/obschie-trebovaniya-optimistichnye-obnovleniya.md)).

* Пока выполняется переход после действия (отметка, удаление), повторное действие игнорируется.

* Права проверяются на сервере; клиент не выполняет собственной проверки владения.

* Мягко удалённые питомцы в списке питомцев записи не показываются.

## Обработка ошибок

| Ситуация | Что делает система |
| --- | --- |
| Ошибка загрузки (сеть, таймаут, 5xx) | Вместо содержимого — состояние «Не удалось загрузить» с пояснением проверить соединение и возможностью «Повторить»; повтор перезапускает запрос данных записи и возвращает скелетон. Возможность вернуться назад сохраняется |
| 404 при загрузке (запись удалена или закрыта на другом устройстве, мягко удалена, принадлежит недоступному питомцу) | Состояние «Событие не найдено» (для напоминания — «Напоминание не найдено») с пояснением, что запись могла быть удалена на другом устройстве, и возможностью вернуться в календарь |
| 404 при обновлении данных, пока экран открыт (после возврата из формы или по инвалидации) | То же состояние «не найдено»; экран не закрывается сам |
| 401 | Не обрабатывается как ошибка загрузки: срабатывает авто-refresh токена (см. [Общие требования: Сессия, 401 и авто-refresh токена](../common/obschie-trebovaniya-sessiya-401-i-avto-refresh-tokena.md)) |
| Ошибка действия над записью (изменение, удаление, отметка) | Реакция определяется правилами соответствующего сценария: [Редактирование события — Frontend](redaktirovanie-sobytiya-frontend.md), [Удаление события — Frontend](udalenie-sobytiya-frontend.md), [Напоминания — Frontend](napominaniya-frontend.md) (таблица ошибок). Сообщение показывается там, где пользователь находится в этот момент |
| `403` на действие (роль изменилась на другом устройстве) | Данные записи обновляются, показывается сообщение, что действие недоступно |
| `409` на отметку («напоминание ещё не наступило») | Сообщение об ошибке, данные обновляются, блок отметки исчезает |
| Ошибка планирования локальных уведомлений после действия | Отдельное сообщение; напоминания остаются (см. [Напоминания — Frontend](napominaniya-frontend.md), «Локальные уведомления») |
| Файл не открылся (нет доступа к временной ссылке, повреждён) | Сообщение об ошибке в просмотре; экран записи не меняется. Временная ссылка на файл не хранится дольше жизни экрана; просроченная ссылка получается повторной загрузкой данных записи |
| Превышен лимит файлов (`409` в формах) | Обрабатывается в формах, см. [Файлы события — Frontend](fayly-sobytiya-frontend.md) |

## Хранение состояния и побочные эффекты

* Данные записи кэшируются отдельно от списков: факт — по `id` события, напоминание — по `id` напоминания. Кэш обновляется инвалидацией/refetch после успешной мутации, а при возврате на экран после изменения (раздел E) патчится оптимистично тем же diff, что отправляется на сервер, — иначе пользователь после сохранения увидел бы старые данные (см. [Общие требования: Оптимистичные обновления (dataSource=network)](../common/obschie-trebovaniya-optimistichnye-obnovleniya.md), раздел «Какие кэши обновляются оптимистично»). Кэш удалённой или закрытой записи удаляется.

* Список дня, сетка месяца, превью событий и «События питомца» обновляются мутациями по правилам соответствующих сценариев; экран записи собственных кэшей списков не ведёт.

* Все мутации (изменение, удаление, отметка) выполняются сценариями, на которые экран ведёт; экран сам запросов записи не отправляет.
