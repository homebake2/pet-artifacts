## Назначение

Определяет, как экран показывает факт или напоминание, когда активен режим `dataSource=local`: сервера нет, данные читаются из локального хранилища.

## Источник данных

* **Факт** читается по `id` из локальной коллекции событий. Файлы — элементы `files` записи; питомцы — по `petIds` (мягко удалённые питомцы не показываются). Автор не показывается: в локальном режиме единственный пользователь.

* **Напоминание** читается по `id` из коллекции `reminders` вместе со своими настройками из `reminderPlans`: тип, значение, питомцы, расписание (`frequencyType`, `weekdays`, `intervalDays`, `times`, `startDate`, `endDate`), источник (`source`, `sourceId`, название связанной записи Ветпаспорта читается из самой записи). Число оставшихся напоминаний — число незавершённых (`closedAt` не задан) напоминаний тех же настроек, включая открытое. Заметка — собственная заметка напоминания, а при её отсутствии — заметка настроек. Файлы настроек и собственные файлы напоминания читаются из локального хранилища.

Состояний «Не удалось загрузить» и сетевых ошибок нет. Запись читается без обращения к сети; скелетон допустим только на время чтения хранилища.

## Отличия от сетевого режима

1. Запись с неподтверждённой операцией не существует: запись в хранилище завершается до возврата пользователя на экран, индикации «синхронизируется» и «требует внимания» нет. После изменения экран записи показывает данные, прочитанные из хранилища.

2. Файлы показываются по локальным путям без временных ссылок; просмотр файла работает так же: фотографии — полноэкранный просмотр с перелистыванием и (на iOS) возможностью поделиться, документы — средствами ОС (система предлагает открыть локальный файл в просмотрщике либо подходящем приложении). Если файл отсутствует или повреждён, элемент показывается с плейсхолдером «не удалось загрузить», как в форме (см. [Файлы события — Frontend (dataSource=local)](fayly-sobytiya-frontend-local.md)).

3. Удаление факта выполняется без окна отмены: после подтверждения действие блокируется и показывает индикатор до завершения записи в хранилище, затем экран закрывается и пользователь возвращается на экран, с которого он был открыт (см. [Удаление события — Frontend (dataSource=local)](udalenie-sobytiya-frontend-local.md)). Вариант «Убрать только у {питомец}» работает так же, как в локальном режиме.

4. Отметка, изменение и удаление напоминания выполняются по правилам [Напоминания — Frontend (dataSource=local)](napominaniya-frontend-local.md); экран закрывается или возвращается к обновлённым данным по правилам раздела E общей страницы после завершения записи. Вопрос о следующей вакцинации после отметки «Выполнено» задаётся так же, как в сетевом режиме.

5. Состояния «Событие не найдено» и «Напоминание не найдено» (запись отсутствует, принадлежит другому аккаунту, мягко удалена, напоминание закрыто, питомцы удалены) — аналог 404 сетевого режима, с возможностью вернуться в календарь.

## Обработка ошибок

| Условие | Что делает клиент |
| --- | --- |
| Запись не найдена, закрыта, принадлежит другому аккаунту или мягко удалена | Состояние «не найдено» с возможностью вернуться в календарь |
| Ошибка чтения локального хранилища | Состояние «Не удалось загрузить» с возможностью «Повторить» |
| Ошибка записи в хранилище при действии над записью | Сообщение об ошибке, пользователь остаётся на экране записи с неизменёнными данными |
| Файл по локальному пути отсутствует или повреждён | Плейсхолдер «не удалось загрузить» без отдельного сообщения |
