Общий механизм интеграции с S3-совместимым хранилищем файлов (Backblaze B2). Страница фиксирует сам механизм доступа к хранилищу (presigned URL, TTL, переменные окружения) — независимо от того, какая сущность (питомец, событие и т.п.) им пользуется. Прикладной API, которым сущности подключаются к этому механизму, — единый generic-эндпоинт загрузки, а не отдельный набор ручек на каждую сущность, см. [Общие требования: Файлы сущностей](obschie-trebovaniya-fayly-sushchnostei.md).

## Модель доступа: presigned URL

Backend не проксирует байты файла через себя и не выдаёт клиенту постоянные S3-ключи. Вместо этого:

* Backend хранит access key (`keyID`) и secret key (`applicationKey`) для S3-совместимого хранилища только на своей стороне, в переменных окружения. Значения ключей никогда не передаются клиенту.
* Для загрузки файла клиент запрашивает у backend временную подписанную ссылку (presigned PUT URL) на конкретный объект в хранилище. Backend выдаёт ссылку только после проверки, что операция разрешена текущему пользователю, и подписывает её своими ключами.
* Клиент загружает файл напрямую в S3 по полученной ссылке, минуя backend.
* После успешной загрузки клиент отдельным запросом привязывает загруженный файл к сущности — backend записывает путь/идентификатор объекта в БД.
* Для чтения файла клиент аналогично запрашивает у backend временную подписанную ссылку (presigned GET URL) на нужный объект; backend выдаёт её только владельцу ресурса, к которому файл привязан.

## Проверка владения

Выдача presigned URL — как на запись, так и на чтение — проходит ту же проверку владения ресурсом, что описана в [Общие требования: IDOR и владение ресурсами](../common/obschie-trebovaniya-idor-i-vladenie-resursami.md): если сущность, к которой относится операция, не существует, мягко удалена или принадлежит другому пользователю — единый 404, ссылка не выдаётся.

## Время жизни подписанных ссылок

Presigned URL выдаются с ограниченным TTL (короткое время жизни — порядка десятков секунд/нескольких минут), достаточным для выполнения одной операции загрузки или чтения. Конкретное значение TTL — деталь реализации backend.

## Переменные окружения

Backend получает доступ к S3-хранилищу через переменные окружения (значения не хранятся в репозитории):

* endpoint хранилища (S3-совместимый API, Backblaze B2);
* access key (`keyID`);
* secret key (`applicationKey`).

Frontend не хранит и не использует S3-ключи — только presigned URL, полученные от backend на конкретную операцию.
