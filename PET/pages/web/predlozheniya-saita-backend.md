## Назначение

Бэкенд принимает и сохраняет предложения, отправленные с формы «Новые идеи» на сайте. Метод не имеет отношения к аккаунтам мобильного приложения и не вызывается мобильным клиентом.

## `POST /web/suggestions`

Контракт описан в отдельной спецификации `open-api/web-spec.json` (не входит в `open-api/spec.json`).

**Доступ.** По ключу сайта в заголовке `X-Api-Key`, токены пользователя не используются:

* если ключ сайта не задан в конфигурации сервера (`WEB_API_KEY`), метод отключён и отвечает как несуществующий маршрут — `404`; пустой ключ доступа не даёт;
* отсутствующий или неверный ключ — `401`;
* значение ключа не пишется в логи.

**Запрос** (`application/json`, тело не больше 64 КБ):

| Поле | Тип | Правила |
|---|---|---|
| `userId` | string | Обязательное. Соответствует `^[A-Za-z0-9_-]{1,64}$`: `local` (локальный режим приложения), uuid аккаунта либо `anonymous`. Существование аккаунта не проверяется. |
| `category` | enum | Обязательное. `pets`, `calendar`, `reminders`, `dynamics`, `access`, `other`. |
| `title` | string | Обязательное. После обрезки пробелов 1–200 символов (считаются символы, не байты). |
| `body` | string | Необязательное. После обрезки пробелов до 5000 символов. |
| `contact` | string | Необязательное. После обрезки пробелов до 200 символов. |
| `consent` | boolean | Обязательное, должно быть `true` — согласие на обработку персональных данных (см. [Общие требования: Согласие на обработку ПД и версии политик](../common/obschie-trebovaniya-soglasie-na-obrabotku-pd-i-versii-politik.md)). Отсутствие или `false` — `400 VALIDATION_ERROR` с указанием поля. |

**Ответы:**

* `201` — предложение сохранено; тело `{ "id": <uuid> }`.
* `400` — тело не является корректным JSON (`BAD_REQUEST`) либо данные не прошли валидацию (`VALIDATION_ERROR`); в `payload` перечислены проблемные поля с причинами. Все ошибки валидации возвращаются одним ответом.
* `401` — отсутствует или неверен `X-Api-Key`.
* `404` — ключ сайта на сервере не настроен.
* `405` — метод запроса не `POST`.
* `500` — ошибка базы данных; ошибка фиксируется в журнале и мониторинге.

Формат тела ошибок методов сайта — `{ code, message, payload? }` с кодами из спецификации `web-spec.json`.

## Хранение

* Предложение сохраняется в таблицу `suggestion`: идентификатор (uuid, генерируется БД), `user_id`, `category`, `title`, `body`, `contact`, `consent_version` (текущая версия документа `personal_data` на момент отправки), момент создания (он же момент согласия).

* Значения `title`, `body`, `contact` сохраняются после обрезки пробелов по краям; отсутствующие `body` и `contact` сохраняются пустой строкой.

* `user_id` — не внешний ключ, а значения `local` и `anonymous` не соответствуют ни одной записи пользователя.

* При удалении аккаунта в той же операции удаляются все предложения, у которых `user_id` равен uuid этого аккаунта.

* Предложения старше 24 месяцев удаляются автоматической очисткой (см. [Общие требования: Сроки хранения данных](../common/obschie-trebovaniya-sroki-hraneniya-dannyh.md)).

* Предложения не отдаются ни одним методом API; читаются администратором напрямую из хранилища.
