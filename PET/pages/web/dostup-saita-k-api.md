## Назначение

Сайт обращается к бэкенду по собственному контракту и со своим ключом, не раскрывая ключ посетителям.

## Контракт

* Методы сайта (`/web/*`) описаны в отдельной спецификации `backend/open-api/web-spec.json`; источник истины — она. Спецификация не входит в `spec.json` мобильного приложения, мобильный клиент методы сайта не вызывает.

* Копия спецификации хранится в проекте сайта без изменений и обновляется при каждом изменении исходной; типизированный клиент сайта генерируется из неё и не правится вручную.

## Ключ сайта

* Методы сайта защищены ключом в заголовке `X-Api-Key`. Значение ключа задаётся в серверном окружении бэкенда (`WEB_API_KEY`) и в серверном окружении сайта (`WEB_API_KEY`) — одно и то же.

* Адрес бэкенда задаётся серверным окружением сайта (`API_BASE_URL`).

* Ключ никогда не попадает в браузер: ни в код страниц, ни в ответы сайта, ни в публичные переменные окружения.

* Если необходимая переменная окружения сайта не задана, обращение к бэкенду завершается ошибкой, которая посетителю показывается как общая ошибка отправки.

## Схема обращения

* Браузер вызывает только собственные серверные обработчики сайта (`/api/*` на том же адресе). Серверный обработчик сам вызывает бэкенд, добавляя ключ.

* Серверный обработчик самостоятельно проверяет входные данные запроса; недействительные данные не пересылаются бэкенду.

* Запросы сайта к бэкенду не кешируются.

* Серверный обработчик не отдаёт браузеру ничего, кроме результата операции.

## Ответы серверного обработчика

Для приёма предложения (`POST /api/suggestions`):

| Ситуация | Ответ посетителю |
|---|---|
| Предложение сохранено | `201` с идентификатором предложения. |
| Тело запроса не JSON | `400`. |
| Данные не прошли проверку | `400`. |
| Бэкенд ответил не `201` или недоступен | `502`; подробности пишутся в серверный журнал, но не раскрываются. |

## Идентификатор пользователя

* Идентификатор пользователя серверный обработчик берёт из сохранённого контекста приложения (куки `uid`), перепроверяет его на допустимость и подставляет в запрос к бэкенду. Передать идентификатор из тела запроса браузера нельзя: значение в теле игнорируется.

* Если идентификатора нет или он недопустим, используется `anonymous`.

## Окружения

* Для разработки и продакшена используются свои значения `API_BASE_URL` и `WEB_API_KEY`. Продакшен-значения хранятся только в окружении хостинга сайта и не попадают в репозиторий.
