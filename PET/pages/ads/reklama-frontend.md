## Назначение

Пользователь может по собственному желанию открыть отдельный экран с рекламой стороннего рекламодателя и тем самым поддержать сервис. Реклама показывается **только** на этом экране; в остальных частях приложения (главный экран, календарь, карточка питомца, профиль, баннеры, виджеты) рекламы нет. Реклама — необязательный слой: любая проблема с ней не должна мешать работе остального приложения.

## Локальный режим

Функция работает и при `dataSource=local`, и при `dataSource=network`, по одним и тем же правилам. В локальном режиме она дополнительно требует наличия интернета (см. «Доступность функции»). Сама реклама не является данными пользователя, поэтому правило паритета сущностей на неё не распространяется: она не входит в `POST /import/local-data` и в перенос локального аккаунта в сеть.

## Доступность функции

Функция доступна, когда одновременно выполнены условия:

1. рекламная сеть **настроена**: в конфигурации сборки задан идентификатор рекламного блока (`adUnitId`) Рекламной сети Яндекса для текущей платформы (iOS и Android имеют свои идентификаторы);
2. реклама **включена на сервере**: параметр `adsEnabled` из конфигурации приложения (см. «Конфигурация приложения — Frontend») равен `true`. Если конфигурация ещё ни разу не была получена (нет ни свежего, ни протухшего кеша), считается, что реклама выключена;
3. у устройства есть доступ в интернет. Условие проверяется в обоих режимах `dataSource` и вычисляется непрерывно: при потере связи функция становится недоступной, при восстановлении — снова доступной.

Если хотя бы одно условие не выполнено, функция недоступна целиком: на экране настроек нет возможности открыть экран рекламы, SDK не инициализируется, пользователю ничего не объясняется. Параметры сети хранятся в конфигурации сборки, а включение или выключение рекламы у уже выпущенных версий выполняется владельцем сервиса через `adsEnabled` без нового релиза. Реклама, которой нет в конфигурации сборки, не включается серверным флагом.

Если связь пропала, пока экран рекламы уже открыт, он остаётся открытым: уже загруженные объявления остаются в ленте, а подгрузка новых ведёт себя по правилам ошибки подгрузки (см. «Состояния экрана»). Пункт в настройках при этом пропадает до восстановления связи.

## Рекламная сеть и SDK

Целевое решение — **Рекламная сеть Яндекса** через Yandex Mobile Ads React Native plugin (пакет `yandex-mobile-ads`, версия 8.x). Приложение должно быть зарегистрировано в аккаунте Рекламной сети Яндекса.

* Формат объявлений — **адаптивный inline-баннер**: высота подбирается SDK автоматически под ширину экрана устройства. В кабинете Рекламной сети Яндекса для него заводится рекламный блок типа «Лента» отдельно для каждой платформы (iOS и Android); его идентификатор и есть `adUnitId` из конфигурации сборки. Другие форматы SDK (sticky-баннер, межстраничная, с вознаграждением, при открытии приложения) не используются: они нарушают правило «реклама только на экране рекламы по действию пользователя».

* SDK инициализируется вручную при первом открытии экрана рекламы (после выполнения запросов согласия, см. ниже), а не при запуске приложения. Автоматическая инициализация SDK при старте приложения (по умолчанию на Android) должна быть отключена, если SDK это позволяет.

* Согласие пользователя на обработку персональных данных и возрастной признак передаются в SDK при каждой инициализации, до её выполнения (см. «Согласие на показ рекламы»).

* На iOS приложение объявляет идентификаторы рекламных сетей для SKAdNetwork в `Info.plist`.

## Вход на экран рекламы

* На экране настроек, когда функция доступна, имеется возможность открыть экран рекламы. Пункт подписан «Реклама».

* Когда функция недоступна, пункта на экране настроек нет (не отключённый, а отсутствующий).

* Экран рекламы открывается только по действию пользователя. Приложение никогда не открывает его само, не предлагает открыть и не показывает на него ссылки из других экранов, баннеров и уведомлений.

* С экрана рекламы имеется возможность вернуться на экран настроек стандартным для платформы способом навигации «назад».

## Согласие на показ рекламы

Реклама запрашивается у сети только после того, как выполнены запросы согласия:

* запрос согласия на обработку персональных данных рекламной сетью (GDPR) — у всех пользователей, независимо от региона. Имеется возможность согласиться или отказаться. Результат передаётся в SDK методом `MobileAds.setUserConsent`;

* на iOS — системный запрос разрешения на отслеживание (ATT) для доступа к рекламному идентификатору устройства (IDFA). Выполняется после выдачи согласия на обработку данных; при отказе от согласия не выполняется.

Правила:

* Запросы согласия выполняются при первом открытии экрана рекламы, а не при запуске приложения. Пока пользователь не открыл экран рекламы, приложение не обращается к SDK сети и не показывает запросов согласия.

* Решение о согласии на обработку данных запрашивается один раз, хранится на устройстве и не передаётся на сервер сервиса. При каждой инициализации SDK сохранённое решение заново передаётся в SDK.

* Отказ от согласия не блокирует экран рекламы: в SDK передаётся `false`, и сеть показывает неперсонализированную рекламу. Отказ от ATT (или его недоступность) также не блокирует рекламу: она показывается без использования IDFA.

* Возрастной признак (COPPA) передаётся в SDK методом `MobileAds.setAgeRestrictedUser` при каждой инициализации. Приложение предназначено для взрослых пользователей, поэтому передаётся `false` (пользователь не считается ребёнком младше 13 лет).

* Приложение не передаёт SDK геолокацию: опция `location` не включается, разрешение на геолокацию для рекламы не запрашивается.

## Экран рекламы

Экран — вертикальная прокручиваемая лента, в которой объявления (адаптивные inline-баннеры) идут друг за другом.

* Лента состоит из рекламных слотов. Каждый слот независимо запрашивает у сети собственный баннер и занимает высоту, которую вернул SDK. Слот, для которого сеть не вернула объявление, в ленте не отображается (без пустого места и без сообщения об ошибке).

* Лента содержит только рекламные объявления. Других элементов, кроме заголовка экрана и служебных состояний (загрузка, пусто, ошибка), нет.

* Каждое объявление явно помечено как реклама (метка «Реклама»), в соответствии с требованиями сети, App Store и Google Play и законодательства. Объявление не маскируется под содержимое приложения.

* Слоты добавляются в ленту по мере прокрутки: пока пользователь не приблизился к концу уже загруженных баннеров, новые слоты не создаются и баннеры не запрашиваются. Лента не имеет жёсткого конца, пока сеть продолжает отдавать объявления.

* Нажатие на объявление выполняет действие, заданное рекламодателем и сетью (переход на сайт, в магазин приложений и т.п.), и открывается средствами SDK или внешнего приложения/браузера. Приложение не перехватывает и не изменяет это действие.

* Пользователь не может скрыть или пожаловаться на объявление средствами приложения; такие возможности, если они предусмотрены сетью, предоставляет сам SDK внутри объявления.

* Вознаграждения за просмотр или клик пользователю не предусмотрено.

## Учёт показов и кликов

* Показы, клики и конверсии учитывает SDK рекламной сети; приложение сервиса их не считает, не передаёт на сервер сервиса и не хранит.

* Серверной статистики рекламы в сервисе нет: расчёты с рекламодателями и отчётность по доходу пользуются кабинетом рекламной сети.

* Приложение не обязано знать, засчитан ли показ: корректность учёта целиком определяется SDK.

## Состояния экрана

| Состояние | Когда | Что видит пользователь |
| --- | --- | --- |
| Загрузка | Первое объявление ещё не получено | Индикатор загрузки на месте ленты |
| Лента | Получено хотя бы одно объявление | Прокручиваемая лента объявлений |
| Нет объявлений | Сеть ответила, что объявлений нет (нет подходящих рекламодателей) | Нейтральное сообщение, что сейчас реклама недоступна, и возможность обновить ленту |
| Ошибка | Не удалось получить первое объявление (сеть, таймаут, ошибка SDK) | Сообщение об ошибке и возможность повторить загрузку |

* Ошибка подгрузки очередной порции при уже показанных объявлениях не заменяет ленту экраном ошибки: уже загруженные объявления остаются, а в конце ленты имеется возможность повторить подгрузку.

* Ошибки рекламы не отправляются пользователю как системные уведомления и не влияют на остальную работу приложения.

## Приватность и публикация

* Политика конфиденциальности приложения должна описывать использование сторонней рекламной сети и передаваемые ей данные (рекламный идентификатор, технические данные устройства).

* Декларации приватности в App Store и Google Play должны отражать данные, которые собирает SDK выбранной сети. Для Рекламной сети Яндекса (конфигурация по умолчанию) это ID устройства (рекламный идентификатор, при разрешении пользователя) и рекламные данные для стороннего рекламирования; геолокация не собирается, пока не включена опция `location`. Эти данные объявляются в App Store Connect («Конфиденциальность приложения») вручную.

* На iOS приложение объявляет назначение запроса ATT (`NSUserTrackingUsageDescription`) на всех поддерживаемых языках. Privacy manifest приложения не дублирует данные SDK: SDK поставляет собственный манифест (`NSPrivacyTracking = false`, без трекинг-доменов), который объединяется с манифестом приложения.

* Подключение SDK не должно передавать рекламной сети персональные данные пользователя из сервиса (ФИО, email, телефон, данные питомцев).

## Вне охвата

* Реклама в виджетах главного экрана. SDK рекламных сетей в виджетах не работают, и честный учёт показа там невозможен; решение о рекламе в виджетах принимается отдельно.

* Реклама на любых других экранах приложения.

* Собственные (прямые) рекламные кампании сервиса и их серверная часть.

* Условия выплат владельцу сервиса Рекламной сетью Яндекса — вне требований к приложению.

* Медиация и подключение дополнительных сетей (например, для ЕС) — отдельное решение; в этом разделе описана только Рекламная сеть Яндекса.
