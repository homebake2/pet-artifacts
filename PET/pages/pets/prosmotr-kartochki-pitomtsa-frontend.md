## Назначение

Экран детальной карточки питомца: полная информация о питомце и список связанных событий. Точка входа в редактирование, удаление и добавление событий.

## Действующие лица и предусловия

* Инициатор — авторизованный пользователь.

* Переход выполняется из списка питомцев с id выбранного питомца.

## Основной сценарий

1. Пользователь нажимает на карточку или кнопку «Детали» в списке.

2. Система открывает экран «Питомец»: кнопка «Назад» слева, иконка редактирования (карандаш) и действие удаления справа.

3. Система выполняет два независимых запроса: данные питомца — `GET /pet/{id}`; список связанных событий — `GET /pet/{id}/events` (в локальном режиме оба источника — хранилище устройства). Это два независимых запроса с раздельными состояниями загрузки/ошибки — блок событий не должен блокировать отображение уже загруженных данных питомца, и наоборот.

4. На время загрузки данных питомца система показывает индикатор загрузки, отличимый от состояния «данные не найдены» и от состояния ошибки. Блок событий на время своей загрузки показывает собственный индикатор независимо от состояния блока данных питомца.

5. После успешной загрузки система показывает: иконку вида, имя, бейдж стерилизации, «вид • порода», блок деталей (возраст, дата рождения, пол, цвет, тип содержания — только известные поля), заметки (если есть), список связанных событий (в порядке, возвращаемом backend — по убыванию даты события) или блок «Нет событий» с кнопкой добавления первого события.

6. Нажатие иконки редактирования открывает форму редактирования питомца; нажатие «Добавить событие» открывает добавление события; кнопка «Назад» возвращает к списку.

## Бизнес-правила и валидация

* Экран только отображает данные и не содержит форм ввода, кроме перехода в редактирование.

* Единственная точка входа в редактирование питомца с этого экрана — иконка редактирования.

* Экран должен предоставлять действие «Удалить питомца» с диалогом подтверждения (см. страницу «Удаление питомца — Frontend»). После успешного удаления питомца с этого экрана система обязана выполнить автоматическую навигацию на экран списка питомцев.

* Отдельная обработка флага `is_deleted` на этом экране не требуется: backend скрывает мягко удалённых питомцев на уровне `GET /pet/{id}` (возвращает 404), поэтому для фронтенда удалённый питомец неотличим от «не найден» и обрабатывается стандартным состоянием ошибки «питомец не найден». Это соответствует единой политике 404 для чужого/несуществующего/мягко удалённого ресурса (см. «Общие требования: IDOR и владение ресурсами»): попытка получить чужого питомца тоже возвращает 404, без 403, и экран не должен пытаться различать эти случаи.

* Иконка вида питомца — ответственность фронтенда: сопоставление species/icon → конкретная иконка выполняется на клиенте, включая дефолтную (fallback) иконку для значений вне справочника (см. «Список питомцев — Frontend» и «Справочник значений (словари enum)»).

* Данные питомца (`GET /pet/{id}`) и список событий (`GET /pet/{id}/events`) — два независимых запроса; экран не должен объединять их в одно состояние загрузки/ошибки.

## Обработка ошибок

| Ситуация                                                                                    | Что должна показать система                                                                                                                                                                                                                                      |
| ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Питомец не найден (404, в том числе мягко удалённый или принадлежащий другому пользователю) | Отдельный экран/блок «Питомец не найден» с возможностью вернуться к списку.                                                                                                                                                                                      |
| Ошибка сервера или сети при загрузке данных питомца (500 и т.п.)                            | Отдельный блок ошибки с сообщением и кнопкой «Повторить», отличимый от «не найден» и от состояния загрузки. Кнопка «Повторить» перезапускает только упавший запрос — данные питомца или события, но не оба сразу (см. «Общие требования: UI-паттерны запросов»). |
| 401 (истёкшая/некорректная авторизация) на любом из двух запросов                           | Не обрабатывается как обычная ошибка экрана — срабатывает единый механизм авто-refresh токена (см. «Общие требования: Сессия, 401 и авто-refresh токена»); отдельное сообщение об ошибке авторизации на этом экране не показывается.                             |
| Сбой только блока событий (данные питомца загрузились успешно)                              | Блок событий показывает собственное degraded-состояние с кнопкой точечного «Повторить», которая перезапускает только запрос событий; остальная карточка питомца продолжает отображаться (см. «Общие требования: UI-паттерны запросов»).                          |
| Отсутствующие необязательные данные питомца (например, не указан пол или цвет)              | Соответствующие блоки на карточке не отображаются, ошибка не показывается.                                                                                                                                                                                       |
| dataSource=local: питомец не найден                                                         | Не описано в данной итерации — будет проработано отдельно в требованиях локального режима (см. «Локальный режим (dataSource=local) — заглушка»).                                                                                                                 |

## Хранение состояния и побочные эффекты

* Экран сам не изменяет данные.

* После успешного редактирования или удаления питомца на этом экране система должна инвалидировать кэш карточки питомца и кэш списка питомцев.

* После успешного удаления питомца система выполняет автоматическую навигацию на экран списка питомцев.
