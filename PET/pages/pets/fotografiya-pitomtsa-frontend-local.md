## Назначение

Определяет, как хранится и отображается фотография питомца, когда активен режим `dataSource=local`. В этом режиме нет сервера и нет S3 — фотография хранится непосредственно на устройстве, без загрузки куда-либо.

## Хранение

Локальная запись питомца (см. «Локальный режим (dataSource=local)», раздел «Модель хранения») получает дополнительное поле `photoUri` (nullable, string) — путь/URI файла фотографии в постоянном хранилище приложения на устройстве (не временный кэш-путь пикера изображений — выбранный файл копируется в постоянную директорию приложения, чтобы остаться доступным после перезапуска приложения и очистки временных файлов ОС).

Загрузка/замена фотографии для локального питомца — синхронная с точки зрения пользователя операция: клиент копирует выбранный файл в постоянное хранилище приложения и записывает `photoUri` в локальную запись питомца по её `id`; отдельного шага «upload-url/complete», описанного для сетевого режима, здесь нет — он существовал в сетевом режиме только из-за необходимости передать файл на сервер.

Удаление фотографии — обнуление `photoUri` в локальной записи питомца и удаление файла из постоянного хранилища приложения; повторное удаление уже отсутствующей фотографии идемпотентно, как и в сетевом режиме.

## Отображение

Карточка питомца и карточки в списке питомцев в режиме `local` отображают фотографию напрямую по `photoUri` (локальный файл, без сетевого запроса и без TTL — в отличие от `photo_url` в сетевом режиме). Если `photoUri` — `null`, либо файл по этому пути отсутствует/повреждён — показывается тот же fallback (иконка вида), что и в сетевом режиме (см. «Фотография питомца — Frontend», раздел «Отображение фотографии»); отдельного сообщения об ошибке не показывается.

## Обработка ошибок

Ошибка копирования файла в постоянное хранилище или записи `photoUri` показывается пользователю тем же способом, что и сбой сохранения в сетевом режиме (см. [Общий раздел «Обработка ошибок хранилища»](../common/lokalnyi-rezhim-datasource-local-zaglushka.md)); ранее отображавшаяся фотография (если была) не изменяется.

## Перенос фотографии при local → network

Перенос данных `POST /import/local-data` (см. «Импорт локальных данных — Backend») не принимает бинарное содержимое `photoUri` в своём JSON-теле — контракт этого эндпоинта рассчитан только на текстовые поля питомца. Вместо этого фотография переносится отдельным шагом, который клиент выполняет сразу после успешного основного переноса, используя поле `pets` ответа `POST /import/local-data` (см. «Импорт локальных данных — Backend», раздел 3) для сопоставления перенесённого локального питомца с его новым серверным `id`.

### Формирование очереди

После успешного `POST /import/local-data` клиент формирует очередь переноса фотографий: по одному элементу для каждого перенесённого питомца, у которого локальная запись имела непустой `photoUri`. Если ни у одного перенесённого питомца не было фотографии — очередь пуста, и никаких дополнительных действий/индикаторов не требуется, основной сценарий переноса (см. «Перенос локального аккаунта в сеть — Frontend», «Импорт из локального аккаунта — Frontend») завершается как обычно.

### Фоновый перенос

Если очередь непуста:

* Основной сценарий переноса (создание/выбор сетевого аккаунта и перенос питомцев/событий/профиля) считается завершённым сразу после успешного `POST /import/local-data` — клиент НЕ держит основной блокирующий индикатор загрузки/диалог в ожидании переноса фотографий. Пользователь сразу получает управление приложением: диалог закрывается либо происходит переход на главный экран сетевого режима (в зависимости от сценария, см. соответствующие Frontend-страницы), и пользователь может продолжать пользоваться приложением как обычно — включая экраны с только что перенесёнными питомцами (до завершения переноса их фотографии они отображаются без неё, с fallback-иконкой вида, см. «Фотография питомца — Frontend», раздел «Отображение фотографии»).

* Клиент показывает ненавязчивый неблокирующий индикатор фонового переноса (например, компактный баннер вида «Переносим фото питомцев: N») — он не перекрывает экран и не блокирует навигацию или любые другие действия пользователя; в отличие от индикатора основного переноса (см. «Общие требования: UI-паттерны запросов»), этот индикатор не привязан к состоянию загрузки конкретной кнопки/формы.

* Клиент переносит фотографии из очереди последовательно, по одной (не параллельно), используя для каждой тот же сценарий, что и при обычной загрузке фотографии в сетевом режиме (см. «Фотография питомца — Frontend», раздел «Загрузка/замена фотографии»: чтение байт файла по локальному `photoUri`, `POST /files/upload-url` с `owner_type: "pet_photo"` и `owner_id` = серверный id питомца → `PUT` в S3 → `POST /files/{file_id}/complete`), где серверный id питомца берётся из сопоставления `local_id → id`.

* После успешного переноса каждой фотографии клиент инвалидирует кэш карточки и списка питомцев (та же инвалидация, что при обычной загрузке фотографии) — так, чтобы фотография появилась при следующем обращении к этим экранам без ручного обновления пользователем.

* Если перенос отдельной фотографии завершается ошибкой (тот же набор причин, что при обычной загрузке — см. «Фотография питомца — Frontend», раздел «Обработка ошибок») — клиент пропускает её и переходит к следующей в очереди; повторная попытка для этой фотографии автоматически не выполняется. Соответствующий питомец остаётся без фотографии в сетевом режиме; пользователь может загрузить её вручную с карточки питомца (обычный сценарий «Загрузка/замена фотографии»), как для любого питомца без фотографии.

* Когда очередь исчерпана (успешно или с пропусками), индикатор фонового переноса скрывается. Если хотя бы один перенос фотографии завершился ошибкой, клиент однократно показывает итоговое ненавязчивое уведомление с числом фотографий, которые не удалось перенести (например, «N фото не удалось перенести, добавьте их вручную на карточках питомцев») — тихая потеря информации о том, что часть фотографий не перенеслась, недопустима, по тому же принципу, что и в остальных местах этого документа.

### Ограничение: перенос не переживает закрытие приложения

Очередь фонового переноса фотографий существует только в памяти текущего запуска приложения и не сохраняется как персистентная задача. Если приложение закрывается (или процесс убивается ОС) до того, как очередь исчерпана, оставшиеся в очереди фотографии не переносятся автоматически — это явно зафиксированное ограничение, а не тихий пробел. Данные при этом не теряются: исходный локальный файл фотографии (`photoUri`) остаётся на устройстве без изменений (см. «Локальный режим (dataSource=local)», раздел «Переключение источника данных» — перенос никогда не удаляет исходные локальные данные), а соответствующий питомец в сетевом режиме уже существует, и его фотографию можно загрузить вручную тем же способом, что и любому питомцу без фотографии.
