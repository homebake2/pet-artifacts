## Назначение

Эндпоинт `GET /pet/{id}` должен возвращать полную информацию об одном питомце по идентификатору, для экрана «Карточка питомца». Эндпоинт `GET /pet/{id}/events` возвращает связанные с питомцем события для блока «События» на том же экране — см. отдельный раздел ниже.

## Действующие лица и предусловия

* Инициатор — авторизованный владелец питомца.

* Требуется валидный access-токен и известный id питомца.

## Основной сценарий

`GET /pet/{id}`. Заголовок `Authorization` обязателен; `LanguageCode` не требуется (см. правило ниже).

1. Система разбирает `id` из пути как UUID.

2. Система проверяет `Authorization` и находит `profileID`.

3. Система ищет питомца по `id = ... AND profile_id = ... AND deleted_at IS NULL`.

4. Если питомец не найден (не существует, принадлежит другому профилю или мягко удалён) — система возвращает `404`.

5. Если питомец найден — система возвращает его полные данные с кодом `200`.

## Бизнес-правила и валидация

* Доступ к питомцу строго ограничен `profile_id` из токена; попытка получить чужого питомца должна возвращать `404`, а не `403` — это осознанное решение по безопасности: ответ не должен раскрывать, существует ли запрошенный id вообще (единая политика, см. «Общие требования: IDOR и владение ресурсами»).

* Мягко удалённые питомцы должны быть скрыты этим эндпоинтом точно так же, как и на `GET /pet` — запрос на такого питомца возвращает `404`, а не его данные. Это устраняет прежнее несоответствие между списком и карточкой и снимает необходимость в отдельной обработке флага `is_deleted` на фронтенде (см. «Общие требования: Soft-delete»).

* `id` должен быть валидным UUID.

* Заголовок `LanguageCode` не является обязательным параметром (см. PET-44) — он не используется сервером для локализации ответа.

* Nullable-поля ответа (согласно OpenAPI-спеке): `color`, `notes`, `gender`, `habilitation`, `icon` — могут отсутствовать в БД и возвращаются как `null`, а не как пустая строка. Остальные поля ответа считаются обязательными.

## Обработка ошибок

| Статус | Условие                                                                                          |
| ------ | ------------------------------------------------------------------------------------------------ |
| 400    | `id` не является валидным UUID.                                                                  |
| 401    | Токен отсутствует, некорректен или истёк.                                                        |
| 404    | Питомец не найден, принадлежит другому профилю или мягко удалён.                                 |
| 500    | Ошибка получения профиля или БД. Формат тела ошибки — см. «Общие требования: Формат ошибок API». |

## Хранение состояния и побочные эффекты

Операция только читает данные (`GET`) и не изменяет состояние БД.

## Эндпоинт GET /pet/{id}/events

Возвращает список событий, связанных с питомцем, для блока «События» на карточке питомца. Это независимый эндпоинт: клиент запрашивает его отдельно от `GET /pet/{id}` (см. «Просмотр карточки питомца — Frontend») — оба запроса имеют раздельные состояния загрузки/ошибки.

* Проверка владения питомцем идентична `GET /pet/{id}`: если питомец не найден, принадлежит другому профилю или мягко удалён — эндпоинт возвращает `404`, а не пустой список (единая политика, см. «Общие требования: IDOR и владение ресурсами»).

* События сортируются по `date_time` по убыванию (DESC) — сначала самые последние по времени.

* Пагинация — по номеру страницы: query-параметры `limit` (целое, опционально) и `offset` (целое, опционально, по умолчанию 0). Если `limit` не передан — используется значение по умолчанию 50. Максимально допустимое значение `limit` — 200; если клиент передал больше, сервер молча ограничивает выборку до 200 (не возвращает ошибку). Если `limit` или `offset` переданы, но не парсятся как целое число, или отрицательны — сервер отвечает `400`. Запрос к БД — `ORDER BY date_time DESC LIMIT $1 OFFSET $2`. Курсорная пагинация не используется — для MVP объём событий на одного питомца ограничен, offset-пагинации достаточно. Ответ (см. пример структуры в OpenAPI-спеке) — плоский массив событий; отдельного поля с общим количеством/наличием следующей страницы не возвращается в этой итерации. Эти параметры и значения по умолчанию должны быть зафиксированы и в OpenAPI-спеке (см. «Связанные задачи», PET-163).

* Если у питомца нет событий — возвращается пустой список с кодом `200`.

* Коды ошибок 401, 404, 500 и формат тела ошибки — как у `GET /pet/{id}`, см. таблицу выше. Дополнительно этот эндпоинт возвращает `400`, если `limit` или `offset` переданы, но не парсятся как целое число или отрицательны. Формат тела ошибки — см. «Общие требования: Формат ошибок API».
