## Назначение

Форма добавления/редактирования питомца — многошаговая (визард). Состав и порядок полей шага 1 («Основное») одинаков для всех видов. Состав полей последующих шагов зависит от выбранного на шаге 1 вида (`species`): каждая группа видов получает свой набор профильных полей — часть текущих общих полей для неё неприменима и скрывается, плюс к ней добавляются профильные поля, специфичные для этой группы. Поле «Заметки» показывается на профильных шагах для любого вида без исключений.

Эта страница — единственный источник истины для состава шагов и профильных полей по группам видов. Страницы форм добавления/редактирования, backend-страницы создания/обновления и страница карточки питомца ссылаются на неё вместо того, чтобы повторно описывать распределение полей по видам.

## Структура шагов формы

Каждый шаг рассчитан на то, чтобы помещаться на одном экране без прокрутки поверх видимой области — поэтому профильные поля разнесены по нескольким шагам после «Основного», а не собраны в один длинный шаг, а шаг «Характеристики» показывается только тогда, когда группе вида есть что в нём показать помимо Веса (иначе Вес показывается уже на шаге «Детали»).

1. **Шаг 1 «Основное»** — не меняется этой страницей, одинаков для всех видов независимо от группы: Фотография, Имя (обязательное), Вид (обязательное), Порода. Состав, порядок, обязательность и валидация этих полей заданы на странице «Добавление питомца — Frontend» и не переопределяются здесь.

2. **Шаг 2 «Детали»** — существует для всех видов без исключения: Дата рождения, Пол, Цвет — общие для всех групп; Тип содержания и Стерилизован показываются только для групп, где применимы (см. «Поля, убираемые из общих для части групп» ниже) — не убранное поле остаётся на этом же шаге, просто скрывается, шаг как таковой никогда не пропускается. Для групп без отдельного профильного поля (см. «Группы видов и их поля» ниже — на момент этой страницы это «Млекопитающие» и «Не распознанный вид») сюда же добавляется Вес — раз у группы нет собственного профильного поля для отдельного шага «Характеристики», отдельный шаг ради одного только Веса не заводится.

3. **Шаг 3 «Характеристики»** — существует только для групп с собственным профильным полем (на момент этой страницы — «Птицы», «Террариумные рептилии», «Водные и полуводные», «Беспозвоночные», см. «Группы видов и их поля»): Вес плюс профильные поля этой группы. Для этих групп это всегда последний шаг — на нём также показывается поле «Заметки».

4. **Шаг 4 «Другое»** — существует только для группы «Млекопитающие» (единственной с профильными полями, не помещающимися в шаг «Детали» вместе с Весом, — см. ниже); содержит Микрочипирован, Номер микрочипа и поле «Заметки». Для видов без шага 3 и шага 4 (группа «Не распознанный вид») «Заметки» показывается на шаге 2 вместе с Весом — кнопка «Сохранить» в этом случае показывается уже там.

5. Если пользователь на шаге 1 меняет «Вид» после того, как уже заполнил профильные поля другой группы, — при переходе на профильный шаг форма показывает только поля новой группы; значения полей, не входящих в новую группу, не отправляются на сервер (не входят в тело запроса создания/diff редактирования), но не обязаны обнуляться в состоянии формы, если пользователь вернётся к прежнему виду в рамках той же попытки заполнения — сохранение введённых значений между переключениями вида в пределах одной сессии формы является допустимым, но не обязательным поведением (не влияет на данные, отправляемые на сервер).

## Группы видов и их поля

| Группа | Виды (`species`) | Убираются из шага 2 | Есть шаг «Характеристики»? Поля (сверх Веса) | Есть шаг «Другое»? Поля | Число шагов |
| --- | --- | --- | --- | --- | --- |
| Млекопитающие | `DOG`, `CAT`, `HAMSTER`, `GUINEA_PIG`, `RABBIT`, `RAT`, `MOUSE`, `FERRET`, `HEDGEHOG`, `CHINCHILLA`, `MINI_PIG`, `MINI_GOAT` | — | Нет (Вес — на шаге 2) | Да: Микрочипирован, Номер микрочипа | 3 |
| Птицы | `PARROT`, `CANARY`, `CHICKEN`, `DUCK`, `PIGEON` | Стерилизован | Да: Окольцован, Номер кольца | Нет | 3 |
| Террариумные рептилии | `IGUANA`, `GECKO`, `BEARDED_AGAMA`, `SNAKE`, `PYTHON` | Тип содержания, Стерилизован | Да: Требуется УФ-лампа | Нет | 3 |
| Водные и полуводные | `FISH`, `AXOLOTL`, `FROG`, `TURTLE` | Тип содержания, Стерилизован | Да: Тип воды, Объём, л | Нет | 3 |
| Беспозвоночные | `TARANTULA`, `HERMIT_CRAB`, `ANT_FARM`, `SNAIL` | Тип содержания, Стерилизован | Да: Количество особей | Нет | 3 |
| Не распознанный вид | `OTHER` | — | Нет (Вес — на шаге 2) | Нет | 2 |

«Заметки» показывается на последнем существующем шаге для каждой группы: шаг 4 у млекопитающих, шаг 3 у птиц/рептилий/водных/беспозвоночных, шаг 2 у нераспознанного вида — см. «Структура шагов формы» выше.

Правило деления на группы: пять видовых групп покрывают все 30 конкретных значений справочника видов без пересечений (12 + 5 + 5 + 4 + 4 = 30); `OTHER` — единственное значение, не входящее ни в одну видовую группу, и получает набор полей, который был на форме до появления профильных шагов (без удалений и добавлений) — по аналогии с тем, как `OTHER` трактуется разрешительно в таблице применимости типов события (см. «Модель значения события и реестр метрик»): раз конкретный вид неизвестен, система не сужает и не расширяет набор полей относительно текущего поведения.

Группа «Водные и полуводные» намеренно совпадает по составу видов с группой применимости типа события `water_quality` (см. «Модель значения события и реестр метрик») — оба деления отвечают на один и тот же вопрос «питомец содержится в воде или рядом с ней», поэтому переиспользуют одно и то же разбиение видов, а не вводят второе, слегка отличающееся.

## Поля, убираемые из общих для части групп

* **Тип содержания** (`habitation`, enum `indoor`/`outside`/`both`) — осмысленно только для видов, которых можно содержать как в помещении, так и вне его (млекопитающие, птицы). Для террариумных, водных и беспозвоночных видов питомец всегда содержится в собственном ограниченном пространстве (террариум, аквариум, инсектарий) — поле убирается из формы для этих трёх групп.

* **Стерилизован** (`sterilized`, boolean) — ветеринарная стерилизация как регулярная практика применима только к млекопитающим из справочника видов. Поле убирается из формы для птиц, рептилий, водных/полуводных видов и беспозвоночных — пример из требования: питомцу вида `FISH` поле не нужно.

Оба поля остаются в модели данных питомца (в БД и в API) без изменений — они лишь не показываются и не отправляются формой для видов, для которых неприменимы (см. «Добавление питомца — Backend», «Редактирование питомца — Backend»: поля остаются опциональными на уровне API для любого `species`, применимость по виду — только клиентское UX-правило видимости поля в форме, backend не проверяет соответствие переданных полей группе вида питомца).

Поля **Цвет** (`color`) и **Вес** (`weight`) остаются общими для всех групп без исключения — окрас и вес физически измеримы для любого вида справочника, включая беспозвоночных (см. «Модель значения события и реестр метрик», раздел «Диапазоны значений и разнообразие видов»: нижняя граница веса 1 г выбрана именно с учётом улитки и паука).

## Новые профильные поля

| Поле (API) | Подпись на форме | Тип | Группы | Валидация |
| --- | --- | --- | --- | --- |
| `microchipped` | Микрочипирован | boolean | Млекопитающие | — |
| `microchip_number` | Номер микрочипа | строка | Млекопитающие | ≤ 50 символов; поле показывается на форме, только если «Микрочипирован» включено, но само по себе необязательно даже в этом случае |
| `ringed` | Окольцован | boolean | Птицы | — |
| `ring_number` | Номер кольца | строка | Птицы | ≤ 50 символов; поле показывается на форме, только если «Окольцован» включено, но само по себе необязательно даже в этом случае |
| `uv_lamp_required` | Требуется УФ-лампа | boolean | Террариумные рептилии | — |
| `water_type` | Тип воды | enum: `freshwater`, `saltwater` | Водные и полуводные | значение из перечисления |
| `enclosure_volume_l` | Объём, л | число | Водные и полуводные | 0.1–5000 |
| `group_size` | Количество особей | целое число | Беспозвоночные | 1–10000 |

Новое enum-значение `water_type` зарегистрировано в [Справочник значений (словари enum)](../common/spravochnik-znachenii-slovari-enum.md) — эта страница не дублирует сами перечни значений, только ссылается на используемые enum.

Все поля этой таблицы — nullable/опциональны на уровне API и БД для любого питомца независимо от `species`, тем же способом, что и существующие опциональные поля питомца (`color`, `notes`, `gender`, `habitation`) — см. «Добавление питомца — Backend». `microchip_number` и `ring_number` не связаны серверной валидацией со значением `microchipped`/`ringed` соответственно — сервер не требует, чтобы номер был указан только при `true`, и не отклоняет номер при `false`; ограничение «показывать поле номера только когда переключатель включён» — исключительно клиентское поведение формы (условная видимость), а не серверное правило.

## Обязательность полей

Обязательность не меняется: обязательны только «Имя» и «Вид» (шаг 1), как и до появления профильных шагов (см. «Добавление питомца — Frontend», раздел «Бизнес-правила и валидация»). Все поля шагов 2, 3 и 4, включая все новые профильные поля этой страницы и «Заметки», — необязательны для любой группы видов.

## Редактирование питомца

Форма редактирования использует ту же структуру шагов и то же распределение полей по группам видов, что и форма добавления (см. «Основной сценарий» на странице «Редактирование питомца — Frontend»). При открытии формы редактирования группа определяется текущим сохранённым `species` питомца; если пользователь меняет «Вид» на шаге 1 на вид из другой группы, профильный шаг(и) показывает поля новой группы, а diff, отправляемый на сервер (см. «Редактирование питомца — Frontend», шаг «Система вычисляет diff»), включает как изменившиеся поля новой группы, так и явную очистку полей прежней группы, которые были заполнены у питомца, но не входят в набор полей новой группы и поэтому не показываются на форме после смены вида — строковые поля (`microchip_number`, `ring_number`) очищаются пустой строкой, enum/числовые поля (`water_type`, `enclosure_volume_l`, `group_size`) очищаются явным `null` (см. «Редактирование питомца — Backend»), булевы поля (`microchipped`, `ringed`, `uv_lamp_required`) отправляются как `false`. Сравнение diff выполняется по тому же алгоритму нормализации, что описан на странице «Редактирование питомца — Frontend» (строковые поля — через `!==` после trim; булевы/числовые — через `!==` без приведения типов; enum — по строковому значению); для новых полей этой страницы `microchipped`/`ringed`/`uv_lamp_required` нормализуются как булевы, `microchip_number`/`ring_number` — как строковые, `water_type` — как enum, `enclosure_volume_l`/`group_size` — как числовые.
