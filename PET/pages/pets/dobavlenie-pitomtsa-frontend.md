## Назначение

Экран многошаговой формы (визарда) для создания нового питомца. Шаг 1 «Основное» — общие для всех видов поля: фотография, имя, вид, порода — и не зависит от выбора вида. Шаг 2 «Детали» — тоже общий для всех видов шаг (дата рождения, пол, цвет, плюс тип содержания/стерилизация там, где применимо; для видов без отдельного шага «Характеристики» сюда же добавляется вес). Число и состав следующих шагов зависит от вида, выбранного на шаге 1, — см. «Профильные поля питомца по видам» для точного распределения полей по группам видов: шаг «Характеристики» показывается только у групп со своим профильным полем (вес плюс это поле), шаг «Другое» — только у млекопитающих; заметки показываются на последнем шаге для любого вида без исключений. Тот же экран формы используется для редактирования (см. страницу «Редактирование питомца — Frontend»), но система должна визуально различать оба режима.

## Действующие лица и предусловия

* Инициатор — авторизованный пользователь.

* Экран открывается нажатием «+» на экране списка питомцев, без id питомца — это признак режима добавления.

## Основной сценарий

1. Пользователь нажимает «+» на экране списка.

2. Система открывает форму в режиме добавления: заголовок и текст основной кнопки должны однозначно указывать на добавление (например, «Добавить питомца»), отличаясь от текста, используемого в режиме редактирования. Форма — визард из 2, 3 или 4 шагов (точное число зависит от группы вида, см. шаг 5 ниже); индикатор прогресса (например, «Шаг 1 из 3») показывает текущий шаг и их общее число.

3. Шаг 1 «Основное» показывает поля: Фотография (необязательное; выбор изображения из галереи/камеры устройства, см. «Фотография питомца — Frontend», раздел «Фотография при добавлении питомца» — сама загрузка в хранилище выполняется только после успешного создания питомца), Имя (обязательное), Вид (обязательное; допустимые значения — см. «Справочник значений (словари enum)», 31 значение), Порода (свободный текст на уровне API; словарь пород для UI-подсказки, зависящий от выбранного вида, — открытый вопрос, пока не определён контент-командой (см. примечание в «Справочник значений (словари enum)»)). Этот набор полей и их порядок одинаковы для всех видов и не зависят от выбора поля «Вид» (см. «Профильные поля питомца по видам»). Отдельного UI-контрола для иконки питомца на форме нет, и поля `icon` не существует ни в запросе, ни в ответе, ни в хранилище: форма собирает и отправляет только `species`. Отображаемая иконка питомца — исключительно клиентская задача отрисовки (сопоставление «вид → иконка», зона ответственности FE, см. «Список питомцев — Frontend»): значение вычисляется на лету при показе питомца и никогда не сохраняется и не передаётся на сервер как отдельное поле; пользователь не выбирает иконку вручную и не видит такого поля на форме.

4. Пользователь нажимает «Далее» на шаге 1 (кнопка неактивна, пока не заполнены обязательные поля «Имя» и «Вид») и переходит на шаг 2 «Детали»: Дата рождения (не позднее текущей даты), Пол, Цвет — общие для всех видов, плюс Тип содержания и Стерилизован там, где применимо для группы вида, выбранного на шаге 1 (см. «Профильные поля питомца по видам», раздел «Поля, убираемые из общих для части групп») — неприменимое поле на этом шаге не показывается, но сам шаг 2 существует для любого вида без исключений. Для групп без собственного профильного поля (на данный момент — «Млекопитающие» и «Не распознанный вид», см. «Профильные поля питомца по видам», раздел «Группы видов и их поля») на этот же шаг добавляется Вес — раз у группы нет отдельного шага «Характеристики», Вес показывается здесь.

5. Если у группы вида, выбранного на шаге 1, есть собственное профильное поле (на данный момент — «Птицы», «Террариумные рептилии», «Водные и полуводные», «Беспозвоночные»), после шага 2 пользователь нажимает «Далее» и переходит на шаг 3 «Характеристики» — Вес плюс это профильное поле; для этих групп шаг 3 всегда последний и также показывает поле «Заметки» — кнопка на нём называется «Сохранить». Если у группы вида профильных полей, не помещающихся на шаге «Детали», больше одного (на данный момент — только группа «Млекопитающие», у которой Вес уже показан на шаге 2), пользователь переходит на шаг «Другое» с оставшимися полями группы и полем «Заметки», и кнопка «Сохранить» показывается уже на нём. Если у группы вида нет ни шага «Характеристики», ни шага «Другое» (группа «Не распознанный вид»), поле «Заметки» и кнопка «Сохранить» показываются уже на шаге 2. Каждый шаг, кроме первого, предоставляет кнопку «Назад» для возврата к предыдущему шагу без потери введённых на нём данных.

6. Пользователь заполняет поля и нажимает «Сохранить» на последнем шаге формы для выбранного вида.

7. Система блокирует повторное нажатие кнопки «Сохранить» и показывает индикатор сохранения на время выполнения запроса.

8. Система отправляет запрос на создание питомца и ждёт ответа сервера. Если на форме была выбрана фотография, после успешного создания питомца система, не снимая индикатор загрузки, сразу выполняет её загрузку (см. «Фотография питомца — Frontend», раздел «Фотография при добавлении питомца») — для пользователя это часть одного действия «Сохранить».

9. Только после завершения всех действий шага 8 (создание питомца и, если применимо, загрузка фотографии) система переходит назад (на экран списка или карточки, откуда был инициирован переход) и снимает индикатор загрузки.

## Бизнес-правила и валидация

* Обязательные поля на форме: «Имя» и «Вид». Форма не должна отправляться, если хотя бы одно из них не заполнено; система обязана показывать сообщение об ошибке валидации рядом с полем.

* Дата рождения не может быть позднее текущей даты.

* Питомец всегда привязывается к профилю текущего пользователя; форма не позволяет указать другого владельца.

* Поле `is_deleted` не входит в форму и не передаётся в запросе создания.

* Для защиты от дублирования питомца при обрыве соединения после успешного создания на сервере форма генерирует клиентский Idempotency-Key. Формат — UUID v4. Ключ генерируется ОДИН РАЗ на попытку сохранения — при первом нажатии кнопки «Сохранить» на форме (а не при каждой отправке и не при открытии формы) — и хранится в состоянии экрана до навигации с него. При повторной отправке того же запроса после сетевой ошибки или таймаута (см. «Общие требования: UI-паттерны запросов» — повторная попытка) форма ОБЯЗАНА переиспользовать тот же самый ключ, а не генерировать новый: если бы ключ перегенерировался при каждой попытке, сервер видел бы каждую попытку как новый запрос, и Idempotency-Key потерял бы смысл (не защищал бы от дубликата при обрыве соединения после того, как сервер уже успел создать питомца, но ответ не дошёл до клиента). Новый ключ генерируется заново только при следующей отдельной попытке создания питомца (новое открытие формы после успешного сохранения или после явной отмены). Ключ передаётся в заголовке `Idempotency-Key` запроса `POST /pet` (см. страницу «Добавление питомца — Backend» — BE резервирует ключ и дедуплицирует запросы с одинаковым ключом в 24-часовом окне).

* Ограничения длины полей (валидация Zod на форме): «Имя» — не более 100 символов, «Заметки» — не более 1000 символов, «Порода» и «Цвет» — не более 100 символов каждое. Те же ограничения действуют на бэкенде (см. страницу «Добавление питомца — Backend»).

* «Дата рождения» дополнительно ограничена снизу: не может быть раньше, чем 500 лет назад от текущей даты (валидация Zod).

* Дублирующиеся имена питомцев у одного пользователя разрешены — уникальность имени не проверяется и не требуется.

* Поле «Вес», если заполнено, отправляется в том же запросе создания питомца, что и остальные поля формы (см. «Добавление питомца — Backend», где `weight` в теле `POST /pet` приводит к созданию первого события веса для только что созданного питомца) — отдельного запроса на сохранение веса фронтенд не выполняет.

* Кнопка «Назад» на шаге 2, 3 или 4 (переход к предыдущему шагу визарда) — это отдельное действие от выхода с экрана формы: она не показывает диалог подтверждения отмены и не теряет введённые данные ни на текущем, ни на предыдущем шаге. Диалог подтверждения отмены (см. «Обработка ошибок» ниже) относится только к попытке полностью покинуть экран формы (аппаратная/системная кнопка «Назад» устройства или иная навигация прочь с экрана), а не к переходу между шагами внутри формы.

* Видимость полей «Тип содержания»/«Стерилизован» на шаге 2, наличие Веса на шаге 2 либо на отдельном шаге «Характеристики», а также наличие и состав шагов «Характеристики»/«Другое» определяются группой вида, выбранного на шаге 1, — точный список полей по группам см. «Профильные поля питомца по видам». Поля групп, не выбранных пользователем, не показываются на форме и не входят в тело запроса создания.

## Конвертация данных (маппер формы)

Форма (React Hook Form) хранит «Дату рождения» как объект `Date`. Перед отправкой на бэкенд маппер формы обязан явно конвертировать это значение в строку формата `YYYY-MM-DD` — без компонента времени и без учёта часового пояса (берутся календарные год/месяц/день, выбранные пользователем, а не результат UTC-преобразования объекта Date).

## Обработка ошибок

| Ситуация                                                                  | Что должна сделать система                                                                                                                                                                    |
| ------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Пустое имя или не выбран вид                                              | Форма не отправляется; под полем показывается сообщение о необходимости заполнить поле.                                                                                                       |
| Ошибка сервера при сохранении (сеть, 400, 500)                            | Система показывает пользователю сообщение об ошибке (snackbar/alert) и остаётся на форме — введённые данные не теряются, повторная отправка возможна.                                         |
| Пользователь нажимает «Назад» без сохранения                              | Если пользователь пытается покинуть экран с несохранёнными данными, система показывает диалог подтверждения отмены; переход и отмена введённых данных выполняются только после подтверждения. |
| Приложение свёрнуто или закрыто с незаполненным до конца черновиком формы | Черновик формы не сохраняется и теряется при повторном открытии приложения/экрана — это принятое ограничение MVP.                                                                             |

## Хранение состояния и побочные эффекты

* После успешного создания система должна инвалидировать кэш списка питомцев в сетевом режиме, чтобы новый питомец сразу появился на экране списка.

* В локальном режиме питомец появляется в хранилище устройства немедленно после сохранения.
