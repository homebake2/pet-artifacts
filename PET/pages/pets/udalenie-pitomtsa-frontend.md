## Назначение

Позволяет пользователю удалить питомца из своего профиля через интерфейс приложения. Удаление на backend всегда мягкое (см. страницу «Удаление питомца — Backend» и [Общие требования: Soft-delete](../common/obschie-trebovaniya-soft-delete.md)); интерфейс должен предоставлять точку входа для этого действия и подтверждение перед выполнением.

## Действующие лица и предусловия

* Инициатор — владелец питомца.

* Действие доступно со списка питомцев и/или с экрана карточки питомца.

## Основной сценарий

1. Пользователь инициирует удаление питомца: действием на карточке в списке (например, свайп) или кнопкой на экране карточки питомца — аналогично уже реализованному паттерну удаления события в календаре.

2. Система показывает диалог подтверждения с указанием имени питомца и предупреждением о необратимости действия в интерфейсе (восстановление через UI не предусмотрено).

3. Пользователь подтверждает удаление.

4. Система блокирует повторное нажатие и отправляет запрос `DELETE /pet/{id}`, ожидая ответа сервера.

5. После успешного ответа система удаляет питомца из отображаемого списка/закрывает карточку и инвалидирует кэш списка питомцев (и кэш карточки, если она была открыта), а также кэш событий этого питомца (см. раздел «Хранение состояния и побочные эффекты»).

## Бизнес-правила и валидация

* Удалить можно только питомца, принадлежащего текущему пользователю; проверка владения выполняется сервером.

* Действие удаления обязательно сопровождается диалогом подтверждения — не выполняется одним нажатием/свайпом без подтверждения.

* После удаления список питомцев должен быть обновлён без необходимости ручного обновления экрана пользователем.

* Поведение при `dataSource=local` (удаление без обращения к сети) будет описано в отдельных требованиях по локальному источнику данных; в текущей итерации не детализируется.

## Обработка ошибок

Ответ `401` на `DELETE /pet/{id}` обрабатывается общими требованиями по сессии и не описывается здесь отдельно (см. [Общие требования: Сессия, 401 и авто-refresh токена](../common/obschie-trebovaniya-sessiya-401-i-avto-refresh-tokena.md)). Ниже — реакции, специфичные для этого экрана.

| Ситуация                                                                        | Что должна сделать система                                                                                                                                                                                                                     |
| ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 404 при удалении (питомец уже удалён, в т.ч. из-за гонки параллельных запросов) | Система трактует `404` как «уже удалён», а не как ошибку: питомец убирается из списка/карточка закрывается, кэши инвалидируются так же, как при успешном ответе — сообщение об ошибке не показывается (см. [Общие требования: Soft-delete](../common/obschie-trebovaniya-soft-delete.md)). |
| 500 или сетевая ошибка при удалении                                             | Система показывает сообщение об ошибке и оставляет питомца видимым в списке/на карточке — действие не считается выполненным до успешного ответа.                                                                                               |
| Пользователь отменяет диалог подтверждения                                      | Удаление не выполняется, состояние экрана не меняется.                                                                                                                                                                                         |

## Хранение состояния и побочные эффекты

* После успешного удаления (включая случай, когда сервер ответил `404` — см. «Обработка ошибок») система инвалидирует: кэш списка питомцев, кэш карточки удалённого питомца и кэш его событий (например, ключи запросов событий по `petId`), так как эти события становятся недоступны на backend (см. страницу «Удаление питомца — Backend»).

* Восстановление удалённого питомца через интерфейс не предусмотрено в текущей итерации — соответствующего эндпоинта восстановления нет (см. страницу «Удаление питомца — Backend»). Undo/restore рассматривается как возможность в будущей итерации.
