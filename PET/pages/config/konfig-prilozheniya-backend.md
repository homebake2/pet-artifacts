## Назначение

Эндпоинт `GET /config` отдаёт клиенту параметры, которые владелец сервиса может менять без выпуска новой версии приложения. Сейчас в конфигурации один параметр — ссылка для пункта «Обо мне» на экране настроек.

## Контракт

`GET /config`

* Публичный эндпоинт: заголовок `Authorization` не требуется и не проверяется.

* Параметров запроса нет. Ответ не зависит от пользователя, языка, платформы и версии приложения.

Ответ `200`:

```json
{
  "aboutMeUrl": "https://example.com"
}
```

| Поле | Тип | Описание |
| --- | --- | --- |
| `aboutMeUrl` | string, обязательное | Абсолютный `https` URL внешней страницы, которую открывает пункт «Обо мне». На текущем этапе значение — `https://example.com`. |

Набор полей объекта будет расширяться; клиент игнорирует неизвестные поля (см. «Конфигурация приложения — Frontend»). Добавление нового параметра — аддитивное изменение ответа.

## Источник значений и модель данных

Значения хранятся в БД, в таблице `app_config`, и меняются без деплоя сервиса. В таблице ровно одна строка (ограничение на уровне БД); каждый параметр конфигурации — типизированная колонка.

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | boolean, PK, `CHECK (id)` | Всегда `true`; гарантирует единственную строку. |
| `about_me_url` | text, NOT NULL | Источник `aboutMeUrl`. Абсолютный `https` URL (CHECK на префикс `https://`). Значение по умолчанию (посев миграцией) — `https://example.com`. |
| `updated_at` | timestamptz, NOT NULL, default `now()` | Момент последнего изменения. |

Административных методов для изменения конфигурации нет: владелец сервиса меняет значения напрямую в БД. Эндпоинт читает строку при каждом запросе, поэтому изменение вступает в силу без перезапуска сервиса. Новый параметр конфигурации — новая колонка со значением по умолчанию.

## Обработка ошибок

| Статус | Условие |
| --- | --- |
| 500 | Ошибка чтения из БД или строка конфигурации отсутствует. Формат тела — «Общие требования: Формат ошибок API». |

Ошибок `400`/`401`/`403` эндпоинт не возвращает: входных параметров и авторизации нет.

## Хранение состояния и побочные эффекты

Операция только читает строку `app_config`. Сервер не хранит состояние по клиентам и не фиксирует факт запроса.
