## Назначение

При запуске приложения авторизованному пользователю в режиме `dataSource=network` может быть показан один баннер с информацией или предложением. Баннер — необязательный слой поверх приложения: любая проблема с ним не должна мешать работе.

## Локальный режим

При `dataSource=local` функция полностью отсутствует: запрос баннеров не выполняется, состояние «закрыт» не ведётся, баннеры не участвуют в `POST /import/local-data` и в переносе локального аккаунта в сеть. Правило паритета сущностей на баннеры не распространяется, так как баннеры — серверный контент, а не данные пользователя.

## Когда выполняется запрос

* Запрос `GET /banner` выполняется не более одного раза за запуск приложения (запуск процесса), когда одновременно выполнены условия: пользователь авторизован (`dataSource=network`) и корневой экран готов. Баннер никогда не показывается поверх splash-экрана и экранов входа/регистрации. Если пользователь вошёл уже после старта приложения, запрос выполняется после входа, так же один раз за запуск.

* В запросе передаются язык интерфейса (`LanguageCode`), платформа и версия приложения.

* Запрос не блокирует запуск и не показывает индикатор загрузки.

* Ошибка запроса (сеть, таймаут, 5xx, `4xx`, включая `401` после неуспешного авто-refresh) — баннер молча не показывается, повторных попыток в этом запуске нет, сообщение об ошибке и кнопка «Повторить» не показываются. Пустой `items` — тоже ничего не показывается, empty-state не нужен.

* Клиент отправляет `If-None-Match` с `ETag` последнего успешного ответа и при `304` использует сохранённый ответ. Сохранённый ответ привязан к пользователю и языку.

## Выбор баннера

Из `items` (уже отсортированы сервером по приоритету) клиент показывает **не более одного** баннера за запуск приложения:

1. Невалидные по контракту элементы (неизвестный `layout`, отсутствуют обязательные поля шаблона, неизвестный `action`) пропускаются без ошибки пользователю; в лог пишется предупреждение. Неизвестные поля игнорируются, чтобы клиент не ломался от добавления полей на сервере.

2. Баннеры с `frequency = once`, id которых есть в списке закрытых для текущего пользователя, пропускаются.

3. Показывается первый оставшийся. Остальные в этом запуске не показываются и не ставятся в очередь; они могут быть показаны при следующих запусках, пока их не вытеснят более приоритетные.

Ограничения по времени между запусками (cooldown) нет.

## Частота показа

Определяется полем `frequency`:

* `once` — показывается, пока пользователь его не закрыл. Закрытие (любым способом, см. ниже) или выполнение действия баннера помечает его id закрытым; после этого баннер больше не показывается этому пользователю на этом устройстве. Если приложение завершили, не закрыв баннер, пометки нет, и он покажется в следующий запуск.

* `every_launch` — показывается при каждом запуске приложения, независимо от того, закрывал ли его пользователь раньше. Пометка «закрыт» для него не ведётся.

Список закрытых id хранится локально на устройстве отдельно для каждого пользователя (по `userID`), поэтому при смене аккаунта на устройстве второй аккаунт не наследует закрытия первого. После переустановки приложения или на новом устройстве список пуст, и баннер `once` будет показан снова — это принятое поведение, серверной синхронизации закрытий нет. Запись в списке, чьего id больше нет в ответе сервера, может быть удалена при очередном запуске.

Изменение содержимого существующего баннера в БД не сбрасывает пометку «закрыт»; чтобы показать обновлённый `once`-баннер заново, в БД заводится баннер с новым `id`.

## Закрытие

Для баннера любого шаблона:

* Имеется возможность закрыть баннер сразу, не выполняя его действия; закрыть можно и без нажатия на явный элемент (жест «вне баннера» или системная навигация «назад», если это принято платформой для данного шаблона).

* Закрытие не требует подтверждения и не отменяется (undo не нужен).

* Закрытие и выполнение действия баннера оба считаются «закрытием» для частоты `once`.

## Действия

Если у баннера есть действие (`primaryCta`), имеется возможность его выполнить; после выполнения баннер закрывается:

* `url` — `target` открывается во внешнем браузере устройства. Проверок домена на клиенте нет, но открываются только абсолютные `https` URL; иначе действие считается невалидным (баннер при этом показывается без действия, если остальные поля валидны).

* `deeplink` — выполняется переход на внутренний маршрут приложения. Неизвестный клиенту маршрут не вызывает ошибку и не показывает сообщений: баннер просто закрывается.

* `store` — открывается страница приложения в App Store / Google Play в зависимости от платформы.

## Состав шаблонов

Набор полей по шаблонам и обязательность — см. таблицу в «Баннеры — Backend». Поведенческие правила клиента:

* `sheet`, `cover`, `dialog` — заголовок, необязательные надпись/бейдж/текст/картинка и необязательное действие. Если действия нет, баннер содержит только возможность закрыть.

* `carousel` — несколько слайдов (1–10), между которыми имеется возможность переключаться вперёд и назад; текущий слайд и общее число слайдов видны пользователю. Действие `primaryCta`, если есть, доступно на последнем слайде. Имеется возможность пропустить оставшиеся слайды и закрыть баннер, не дойдя до конца; тогда для `once` он считается закрытым. Просмотр последнего слайда сам по себе закрытием не является — баннер закрывается действием или явным закрытием.

* `poster` — только картинка; выполнение действия доступно по нажатию на всю картинку. Если картинка не загрузилась, баннер не показывается вовсе (показывать нечего), и пометка «закрыт» не ставится.

* `tone` определяет только акцентную тональность оформления и не меняет поведения. При `tone = null` используется нейтральная тональность; неизвестное значение трактуется как `null`.

Заголовок ограничивается двумя строками, основной текст — четырьмя; остаток обрезается многоточием, ошибкой это не считается.

## Картинки

* Перед показом клиент предзагружает картинку выбранного баннера (для `carousel` — первого слайда); ожидание не дольше 2 секунд, после чего баннер показывается как есть, а картинка догружается. Пока она не загрузилась, на её месте показывается заглушка (по `blurhash`, если он есть, иначе нейтральный цвет). Скелетон для баннера не используется.

* Если картинка не загрузилась, блок картинки скрывается, остальной текст остаётся (исключение — `cover` и `poster`, где картинка основная: у `cover` без картинки используется оформление без обложки; у `poster` баннер не показывается, см. выше). Картинки следующих слайдов `carousel` загружаются в фоне; слайд с неудавшейся картинкой показывается без неё.

## Локализация

Тексты баннера приходят уже на языке `LanguageCode` запроса (см. «Общие требования: Локализация контента на backend»), клиент их не переводит. Статические надписи самого клиента, которых нет в данных баннера (например, подпись закрытия или «Далее» в `carousel`), берутся из локализации приложения (i18next, en/ru).

## Известные ограничения текущей итерации

* Аналитика (показы, нажатия, закрытия) не ведётся — отдельная функция.

* Закрытия не синхронизируются с сервером.
