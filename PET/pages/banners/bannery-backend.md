## Назначение

Владелец сервиса заводит баннеры через административные методы (см. «Баннеры — Управление (admin API) — Backend») либо напрямую в БД. Эндпоинт `GET /banner` отдаёт авторизованному пользователю список баннеров, которые ему можно показать сейчас, уже локализованных и отсортированных по приоритету. Решение, какой из них и показывать ли вообще, принимает клиент (см. «Баннеры — Frontend»): сервер не хранит состояние «закрыто пользователем».

## Модель данных

### `banner`

Основная таблица; содержит только поля, не зависящие от языка.

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | uuid, PK | Идентификатор баннера. Клиент хранит его как ключ «закрыт» (см. «Баннеры — Frontend»). |
| `layout` | text, enum | Шаблон баннера: `sheet`, `cover`, `dialog`, `carousel`, `poster` (см. «Шаблоны»). |
| `tone` | text, enum, nullable | Тональность: `info`, `attention`, `negative`, `positive`, `promo`. Влияет только на оформление; `null` — нейтральная. |
| `is_show` | boolean, NOT NULL, default `true` | Ручной выключатель. `false` — баннер не отдаётся независимо от окна показа. |
| `starts_at` | timestamptz, nullable | Начало окна показа (включительно). `null` — без нижней границы. |
| `ends_at` | timestamptz, nullable | Конец окна показа (не включительно). `null` — без верхней границы. Если заданы оба, `ends_at > starts_at` (CHECK). |
| `priority` | integer, NOT NULL, default `0` | Чем больше, тем выше в выдаче. |
| `frequency` | text, enum, NOT NULL | Частота показа: `once` или `every_launch` (см. «Баннеры — Frontend»). |
| `cta_action` | text, enum, nullable | Тип действия: `url`, `deeplink`, `store`; `null` — действия нет (см. «Действия»). |
| `cta_target` | text, nullable | Цель действия (URL или внутренний маршрут), общая для всех языков. |
| `created_at` | timestamptz, NOT NULL, default `now()` | |

### `banner_translation`

Переводимые поля баннера по шаблону «Общие требования: Локализация контента на backend». PK `(banner_id, locale)`.

| Поле | Описание |
| --- | --- |
| `overline` | Короткая надпись над заголовком. |
| `title` | Заголовок. |
| `body` | Основной текст. |
| `badge` | Короткая метка (например, «Новая функция», «Реклама»). |
| `image_url` | Абсолютный `https` URL публично доступной картинки (хостинг картинок вне охвата: backend их не хранит и не подписывает). |
| `image_blurhash` | `blurhash` картинки для заглушки; берётся из той же строки, что и `image_url`. |
| `cta_label` | Подпись действия. |
| `secondary_label` | Подпись действия «отложить/пропустить», если шаблон его допускает. |

### `banner_slide` и `banner_slide_translation`

Слайды баннера с шаблоном `carousel`. `banner_slide`: `id` (uuid, PK), `banner_id` (FK на `banner`, `ON DELETE CASCADE`), `position` (integer, порядок показа, `UNIQUE (banner_id, position)`). `banner_slide_translation` — переводимые поля слайда, PK `(slide_id, locale)`: `title`, `body`, `image_url`, `image_blurhash` (правило пары `image_url`/`image_blurhash` то же).

### `banner_targeting`

Условия показа баннера. Одна строка — одно правило определённого типа: `banner_id` (FK на `banner`, `ON DELETE CASCADE`), `type` (text, enum типов правил), `params` (jsonb, параметры правила), `UNIQUE (banner_id, type)`. Добавление нового типа условия — это новый тип правила и его вычислитель в коде backend; изменения структуры таблиц не требуется.

Семантика:

* нет строки правила типа — по этому условию ограничения нет;

* условия разных типов объединяются по **И** (баннер отдаётся, только если выполнены все заданные правила);

* значения внутри одного правила (например, список платформ) объединяются по **ИЛИ**.

Типы правил текущей итерации:

| `type` | `params` | Условие выполнено, если |
| --- | --- | --- |
| `platform` | `{"values": ["ios", "android"]}` | платформа клиента входит в `values` |
| `app_version` | `{"min": "1.2.0", "max": "2.0.0"}` (любой из ключей необязателен) | версия клиента `>= min` и `<= max` (границы включительно; формат `MAJOR.MINOR.PATCH`; сравнение числовое покомпонентное, а не строковое) |
| `language` | `{"values": ["ru"]}` | `LanguageCode` запроса входит в `values` |
| `has_pets` | `{"value": true}` | признак «есть хотя бы один не удалённый питомец» (`deleted_at IS NULL`) у пользователя равен `value` |

Строка правила с неизвестным `type` или `params`, не соответствующими типу, делает баннер невалидным (см. «Невалидные баннеры»).

### `banner_user`

Персональное ограничение показа: `banner_id` → `banner(id) ON DELETE CASCADE`, `user_id` → `users(id) ON DELETE CASCADE`, PK `(banner_id, user_id)`. Если у баннера есть хотя бы одна строка в `banner_user`, он отдаётся **только** пользователям из этого списка (в том числе для проверки баннера в проде до публикации: достаточно указать свой `user_id`). Если строк нет — баннер доступен всем, кто проходит остальные условия. Таблица отделена от `banner_targeting` из-за внешних ключей и каскадного удаления; на семантику это не влияет — это ещё одно условие, объединяемое по **И** с остальными.

## Шаблоны (`layout`) и обязательные поля

Обязательность относится к значению **после выбора языка** (т.е. поле должно иметь значение на языке запроса или на языке по умолчанию).

| `layout` | Состав | Обязательно | Необязательно |
| --- | --- | --- | --- |
| `sheet` | Текст, картинка, действие | `title` | `overline`, `body`, `image_url`, действие, `secondary_label` |
| `cover` | Обложка-картинка, текст, действие | `title`, `image_url` | `badge`, `body`, действие |
| `dialog` | Только текст, действие | `title` | `badge`, `body`, действие |
| `carousel` | Несколько слайдов | 1–10 слайдов, у каждого `title` | `overline`, действие (на последнем слайде), `secondary_label`, `image_url`/`body` слайдов |
| `poster` | Только картинка | `image_url` | `badge`, действие (на весь баннер; `cta_label` не нужен) |

«Просто текст» — `dialog` или `sheet` без картинки; «только картинка» — `poster`. Поля, не перечисленные для шаблона, сервером игнорируются.

## Действия

Действие задаётся парой `cta_action` + `cta_target` и подписью `cta_label` (переводимая):

* `url` — `cta_target` обязателен, абсолютный URL со схемой `https`; клиент открывает его во внешнем браузере. Допустимость домена сервер не проверяет.

* `deeplink` — `cta_target` обязателен, внутренний маршрут приложения. Набор поддерживаемых маршрутов определяет клиент; сервер формат маршрута не проверяет.

* `store` — `cta_target` не используется: клиент открывает страницу самого приложения в магазине текущей платформы.

Для шаблонов, где действие отображается с подписью (`sheet`, `cover`, `dialog`, `carousel`), `cta_label` обязателен; иначе действие считается невалидным.

## Основной сценарий

`GET /banner?platform=<ios|android>&appVersion=<MAJOR.MINOR.PATCH>`

1. Система проверяет токен (`Authorization: Bearer <access_token>`) и извлекает `userID`. Заголовок `LanguageCode` и query-параметры `platform`, `appVersion` обязательны; при ошибке валидации — `400`.

2. Система выбирает кандидатов из `banner`, удовлетворяющих **всем** условиям:

   1. `is_show = true`;

   2. `starts_at IS NULL OR starts_at <= now()` и `ends_at IS NULL OR now() < ends_at`;

   3. выполнены все правила `banner_targeting` баннера (см. таблицу типов правил);

   4. нет строк в `banner_user` для этого баннера либо среди них есть `userID`.

3. Для каждого кандидата система читает строки перевода (баннера и его слайдов) для языка запроса и языка по умолчанию одним запросом, выбирает значения по цепочке из «Общие требования: Локализация контента на backend» и проверяет валидность (см. «Невалидные баннеры»).

4. Результат сортируется по `priority DESC, created_at DESC`.

5. Система возвращает `200 OK` с телом `{"items": [Banner]}`; если подходящих нет — `{"items": []}` со статусом `200`. Ограничения на количество в ответе нет.

Элемент `Banner` в ответе содержит: `id`, `layout`, `tone`, `frequency`, `overline`, `title`, `body`, `badge`, `image` (`{url, blurhash}`), `slides` (`[{image, title, body}]`, по возрастанию `position`), `primaryCta` (`{label, action, target}`), `secondaryLabel`. Все переводимые значения — уже строки на языке запроса. Поля, которых нет у баннера, возвращаются как `null`. Служебные поля (`is_show`, окно, правила таргетинга, `banner_user`, `priority`) в ответ не попадают.

## Невалидные баннеры

БД редактируется вручную, поэтому ошибка в данных не должна ломать выдачу. Баннер исключается из ответа (остальные отдаются как обычно), а причина пишется в лог сервера с `banner_id`, если:

* нарушены обязательные поля шаблона из таблицы выше (в том числе обязательное переводимое поле не имеет значения ни для языка запроса, ни для `ru`);

* `layout`, `tone`, `frequency` или `cta_action` вне enum;

* строка `banner_targeting` имеет неизвестный `type` или `params` не соответствуют типу (в том числе значения платформ вне enum, версии не в формате `MAJOR.MINOR.PATCH`);

* действие не проходит правила раздела «Действия»; у слайда нет `title`; слайдов меньше 1 или больше 10;

* `image_url` не является абсолютным `https` URL.

Невалидный баннер никогда не приводит к ответу `5xx`.

## Кеширование

Эндпоинт возвращает заголовок `ETag`, вычисленный по телу ответа (с учётом языка, см. раздел «Кеширование» общей страницы о локализации). Запрос с `If-None-Match`, совпадающим с актуальным `ETag`, получает `304 Not Modified` без тела. Каждый запрос всё равно пересчитывает набор кандидатов (окна показа, таргетинг), так что баннер включается и выключается без перезапуска сервера.

## Обработка ошибок

| Статус | Условие |
| --- | --- |
| 400 | Отсутствует/некорректен `LanguageCode`, `platform` или `appVersion`. |
| 401 | Заголовок `Authorization` отсутствует, некорректен или токен истёк. |
| 500 | Ошибка выборки из БД. Формат тела — «Общие требования: Формат ошибок API». |

## Хранение состояния и побочные эффекты

Операция только читает данные. Сервер не фиксирует факт показа, закрытия или нажатия — аналитика баннеров вне охвата текущей итерации (отдельная функция). Состояние «закрыт» хранится только на клиенте.
