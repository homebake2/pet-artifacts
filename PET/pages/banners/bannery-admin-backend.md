## Назначение

Методы для владельца сервиса, позволяющие создавать, изменять, просматривать и удалять баннеры одним запросом на баннер, не работая с несколькими связанными таблицами (`banner`, `banner_translation`, `banner_slide`, `banner_slide_translation`, `banner_targeting`, `banner_user`) вручную. Методы не предназначены для мобильного клиента и не входят в клиентский контракт: приложение их не вызывает, клиентский код для них не генерируется. Прямое редактирование БД остаётся допустимым, поэтому чтение (`GET /banner`) по-прежнему защищается от невалидных данных (см. «Баннеры — Backend», «Невалидные баннеры»).

## Доступ

* Методы доступны только по административному ключу в заголовке `X-Admin-Key`. Значение ключа задаётся конфигурацией сервера (переменная окружения); сравнение выполняется за постоянное время.

* Токен пользователя (`Authorization: Bearer`) для этих методов не используется и не даёт доступа; в приложении нет роли «администратор».

* Если ключ в конфигурации сервера не задан, admin-методы отключены и отвечают так, будто маршрута не существует (`404`), чтобы нельзя было получить доступ с пустым ключом.

* Отсутствующий или неверный ключ — `401` в формате «Общие требования: Формат ошибок API». Значение ключа не пишется в логи.

## Представление баннера (`BannerDoc`)

Единый документ, который принимают методы записи и возвращают методы чтения. Он собирает все связанные таблицы в один объект и **не** локализован (содержит все переводы):

```json
{
  "layout": "sheet",
  "tone": "promo",
  "isShow": true,
  "startsAt": "2026-10-20T00:00:00Z",
  "endsAt": "2026-10-31T23:59:59Z",
  "priority": 10,
  "frequency": "once",
  "cta": {"action": "url", "target": "https://example.com/offer"},
  "translations": {
    "ru": {"overline": "АКЦИЯ", "title": "...", "body": "...", "badge": null,
           "image": {"url": "https://...", "blurhash": "..."},
           "ctaLabel": "Записаться", "secondaryLabel": "Не сейчас"},
    "en": {"title": "...", "ctaLabel": "Book"}
  },
  "slides": [
    {"translations": {"ru": {"title": "...", "body": "...", "image": {"url": "...", "blurhash": null}}}}
  ],
  "targeting": [
    {"type": "platform", "params": {"values": ["ios"]}},
    {"type": "app_version", "params": {"min": "1.2.0"}}
  ],
  "userIds": ["<uuid>", "<uuid>"]
}
```

Соответствие таблицам:

* `layout`, `tone`, `isShow`, `startsAt`, `endsAt`, `priority`, `frequency`, `cta.action`, `cta.target` → колонки `banner`; в ответе чтения добавляются `id` и `createdAt`;

* `translations` (карта «код языка → поля») → строки `banner_translation`; ключ карты — `locale`;

* `slides` → строки `banner_slide`; `position` задаётся порядком элементов массива (с 1) и в документе не передаётся; `slides[].translations` → `banner_slide_translation`;

* `targeting` → строки `banner_targeting`;

* `userIds` → строки `banner_user`; пустой массив или отсутствие поля — ограничения по пользователям нет.

Поля, отсутствующие в запросе, трактуются как `null` (для `isShow` — `true`, для `priority` — `0`, для массивов — пустой массив).

## Методы

Все методы требуют `X-Admin-Key`. Тело и ответы — JSON.

### `POST /admin/banner` — создать

1. Система проверяет ключ и валидирует `BannerDoc` (см. «Валидация при записи»).

2. В одной транзакции создаёт запись `banner` с новым `id` и все связанные строки (переводы, слайды, правила, пользователи).

3. Возвращает `201 Created` с полным `BannerDoc` (включая `id`).

### `PUT /admin/banner/{id}` — заменить целиком

1. Система проверяет ключ и валидирует `BannerDoc`.

2. В одной транзакции полностью заменяет баннер и все связанные строки на переданные: то, чего нет в теле, удаляется (переводы, слайды, правила, пользователи).

3. Если баннера с таким `id` нет — создаёт его с этим `id` (это даёт идемпотентную загрузку, в том числе между окружениями) и возвращает `201`; если был — возвращает `200`. Тело ответа — полный `BannerDoc`.

Частичного обновления документа нет: чтобы изменить поле, клиент читает документ и передаёт его целиком. Исключение — переключатель показа ниже.

### `PATCH /admin/banner/{id}` — включить/выключить показ

Тело `{"isShow": true|false}`. Меняет только `is_show` и возвращает `200` с полным `BannerDoc`; `404`, если баннера нет. Нужен, чтобы мгновенно выключить баннер, не пересылая весь документ.

### `GET /admin/banner/{id}` и `GET /admin/banner`

* `GET /admin/banner/{id}` — возвращает `BannerDoc` (все переводы, как хранятся); `404`, если баннера нет.

* `GET /admin/banner` — возвращает `{"items": [BannerDoc]}` **всех** баннеров, включая выключенные, с истёкшим или ещё не наступившим окном; сортировка по `created_at DESC`. Пагинации и фильтров в текущей итерации нет. Выдача не зависит от `LanguageCode` и не применяет таргетинг.

### `DELETE /admin/banner/{id}` — удалить

Физически удаляет баннер и каскадно все связанные строки. `204` при успехе, `404`, если баннера нет. Закрытия пользователей хранятся на клиентах и не затрагиваются.

## Валидация при записи

В отличие от чтения (где невалидный баннер молча пропускается), запись невалидного документа отклоняется целиком: ничего не сохраняется, ответ — `400` с кодом `VALIDATION_ERROR`, а `payload` содержит список всех найденных проблем (путь к полю и причина), а не только первую.

Проверяются все правила раздела «Невалидные баннеры» из «Баннеры — Backend» (обязательные поля шаблона, enum, действие, слайды 1–10, правила таргетинга, `https` у `image.url`), а также:

* `translations` обязан содержать язык по умолчанию (`ru`) и обязательные поля шаблона на нём; для остальных языков поля необязательны;

* ключи `translations` — только поддерживаемые языки (`LanguageCode`);

* если заданы оба `startsAt` и `endsAt`, то `endsAt > startsAt`;

* `userIds` — существующие пользователи; неизвестный `user_id` — ошибка валидации;

* в `targeting` не более одного правила каждого типа;

* `id` в пути `PUT`/`PATCH`/`GET`/`DELETE` — валидный uuid, иначе `400`.

## Обработка ошибок

| Статус | Условие |
| --- | --- |
| 400 | Документ не прошёл валидацию или невалидный `id`. Подробности в `payload`. |
| 401 | Отсутствует или неверен `X-Admin-Key`. |
| 404 | Баннер не найден (`GET`/`PATCH`/`DELETE` по `id`), либо admin-методы отключены конфигурацией. |
| 500 | Ошибка БД; транзакция откатывается, частично записанного баннера не остаётся. |

## Хранение состояния и побочные эффекты

Каждая операция записи выполняется в одной транзакции: баннер либо полностью записан, либо не изменён. Изменения сразу видны в `GET /banner` (кеша данных на стороне сервера нет, `ETag` пересчитывается по телу). Факты создания/изменения/удаления логируются с `banner_id` (без значения ключа).
