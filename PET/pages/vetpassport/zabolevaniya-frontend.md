## Назначение

Секция «Заболевания» таба «Медкарта»: список заболеваний питомца, экраны добавления/редактирования.

## Основной сценарий

1. Секция открывается запросом списка заболеваний питомца — скелетон на время загрузки, пустое состояние при пустом списке (без секции «+ Добавить» это не отменяет — возможность добавить заболевание доступна всегда, независимо от того, пуст список или нет).

2. Список показывает заболевания карточками: название, «Диагноз: {diagnosed_date}», заметка, статус («Активно»/«Вылечено»). Для каждого заболевания имеется возможность открыть форму редактирования и удалить его.

3. Имеется возможность добавить заболевание и открыть форму редактирования существующего (одна форма на оба режима): Название заболевания (обязательное, ≤100), Дата постановки диагноза (обязательная, не позднее текущей даты), Статус — выбор из двух вариантов «Активно»/«Вылечено» (обязательный, по умолчанию «Активно» при создании), Заметка (опционально, ≤1000, multiline), блок прикрепления файлов (до 10 — см. «Общие требования: Файлы сущностей»).

4. «Сохранить» применяет результат оптимистично и сразу возвращает на таб «Медкарта», не дожидаясь ответа сервера (см. «Общие требования: Оптимистичные обновления (dataSource=network)»).

5. Удаление — оптимистичное, с окном отмены (см. там же, раздел «Оптимистичное удаление с окном отмены (Undo)»). Пока созданная запись не подтверждена сервером (временная карточка с индикацией «синхронизируется»), она доступна только для просмотра: открыть, отредактировать и удалить её нельзя (см. там же, раздел «Визуальная индикация фоновой синхронизации»).

## Бизнес-правила и валидация

* Обязательные поля: «Название заболевания», «Дата постановки диагноза», «Статус».

* «Дата постановки диагноза» не может быть позднее текущей даты (валидация формы; сервер такую проверку не выполняет — см. «Заболевания — Backend»). Сравниваются календарные дни, а «текущая дата» определяется в момент проверки формы, а не в момент её открытия.

## Обработка ошибок

| Ситуация | Что делает система |
| --- | --- |
| Не заполнено обязательное поле | Форма не отправляется, сообщение под полем |
| Транзиентная ошибка сервера при сохранении (нет сети/таймаут/5xx) | Оптимистичное изменение остаётся применённым, запрос уходит в очередь фоновых повторов, карточка показывает индикатор «синхронизируется» (см. «Общие требования: Оптимистичные обновления», разделы «Классификация ошибок мутации», «Очередь фоновых мутаций и повторные попытки») |
| Постоянная ошибка сервера при сохранении (400/403/409) | Оптимистичное изменение откатывается, пользователю показывается сообщение об ошибке; введённые данные для повторной отправки не сохраняются (см. там же, «Обработка ошибок и откат») |
| Отложенный `DELETE` не доставлен — транзиентная ошибка | Запрос уходит в очередь фоновых повторов, заболевание остаётся удалённым из списка без отката (см. там же, «Оптимистичное удаление с окном отмены (Undo)») |
| Отложенный `DELETE` завершился постоянной ошибкой / повторы исчерпаны | Заболевание восстанавливается в списке, сообщение об ошибке с возможностью повторить удаление (см. там же) |
| Заболевание уже удалено на другом устройстве | Тихо убрать из списка / «уже удалено», без сообщения об ошибке (см. «Общие требования: Soft-delete») |

## Хранение состояния и побочные эффекты

После создания/редактирования/удаления — инвалидация кэша списка заболеваний питомца; этот кэш списка патчится синхронно и оптимистично (см. «Общие требования: Оптимистичные обновления (dataSource=network)»).
