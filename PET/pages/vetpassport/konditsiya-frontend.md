## Назначение

Поле «Кондиция» вверху таба «Медкарта» — выпадающий список из значений справочника «Ветпаспорт — Кондиция» (см. [Справочник значений (словари enum)](../common/spravochnik-znachenii-slovari-enum.md)), рядом с которым в этой же итерации веса нет — вес в этот флоу не входит (управляется отдельно на форме питомца, см. «Добавление питомца — Frontend»).

## Основной сценарий

1. Таб «Медкарта» открывается вместе с остальными данными питомца; поле «Кондиция» предзаполняется текущим значением `pet.body_condition` (пустое — если `null`).

2. Выбор значения в выпадающем списке сразу (без отдельной действия «Сохранить» для этого поля) применяется оптимистично в поле и отправляет `PUT /pet/{id}` с `{body_condition: <выбранное значение>}` в фоне, не дожидаясь ответа сервера (см. «Общие требования: Оптимистичные обновления (dataSource=network)»).

3. Выбранное значение сразу отображается в самом поле. Кэш карточки питомца оптимистично не патчится (кэш детали одной записи) — после подтверждения сервером он обновляется инвалидацией/refetch, согласуя значение на других экранах, читающих `GET /pet/{id}` (см. «Общие требования: Оптимистичные обновления», раздел «Какие кэши обновляются оптимистично»).

## Бизнес-правила и валидация

* Поле опционально — «Кондиция» может оставаться незаполненной сколь угодно долго.

* Допустимые значения — только значения справочника; UI не позволяет ввести произвольный текст (закрытый список, не свободный ввод).

## Обработка ошибок

| Ситуация | Что делает система |
| --- | --- |
| Транзиентная ошибка сервера при сохранении (нет сети/таймаут/5xx) | Значение поля остаётся применённым, запрос уходит в очередь фоновых повторов (см. «Общие требования: Оптимистичные обновления», разделы «Классификация ошибок мутации», «Очередь фоновых мутаций и повторные попытки») |
| Постоянная ошибка сервера при сохранении (400/403/409) | Поле откатывается к прежнему значению (см. там же, «Механизм: снимок, применение, откат»), пользователю показывается сообщение об ошибке; повторный выбор значения запускает новую попытку с нуля |
| Питомец уже удалён на другом устройстве (404) | Тихо уйти с экрана / показать «уже удалено», без сообщения об ошибке |

## Хранение состояния и побочные эффекты

Кэш карточки питомца патчится синхронно и оптимистично в момент выбора значения; после успешного ответа сервера — сверка данными ответа (см. «Общие требования: Оптимистичные обновления (dataSource=network)»).
