## Назначение

Поле «Кондиция» вверху таба «Медкарта» — выпадающий список из значений справочника «Ведпаспорт — Кондиция» (см. [Справочник значений (словари enum)](../common/spravochnik-znachenii-slovari-enum.md)), рядом с которым в этой же итерации веса нет — вес в этот флоу не входит (управляется отдельно на форме питомца, см. «Добавление питомца — Frontend»).

## Основной сценарий

1. Таб «Медкарта» открывается вместе с остальными данными питомца; поле «Кондиция» предзаполняется текущим значением `pet.body_condition` (пустое — если `null`).

2. Выбор значения в выпадающем списке сразу (без отдельной кнопки «Сохранить» для этого поля) отправляет `PUT /pet/{id}` с `{body_condition: <выбранное значение>}`. Поле показывает индикатор загрузки на время запроса и блокируется от повторного выбора (см. «Общие требования: UI-паттерны запросов»).

3. После успеха — поле остаётся с новым значением; кэш карточки питомца инвалидируется, чтобы значение было согласовано на других экранах, читающих `GET /pet/{id}`.

## Бизнес-правила и валидация

* Поле опционально — «Кондиция» может оставаться незаполненной сколь угодно долго.

* Допустимые значения — только значения справочника; UI не позволяет ввести произвольный текст (закрытый список, не свободный ввод).

## Обработка ошибок

| Ситуация | Что делает система |
| --- | --- |
| Ошибка сервера при сохранении | Snackbar/alert с сообщением об ошибке; поле возвращается к прежнему значению (оптимистичное обновление откатывается) |
| Питомец уже удалён на другом устройстве (404) | Тихо уйти с экрана / показать «уже удалено», без error-тоста |

## Хранение состояния и побочные эффекты

Инвалидация кэша карточки питомца после успешного сохранения.
