## Назначение

Таб «Аллергии»: список аллергий питомца, экраны добавления/редактирования.

## Основной сценарий

1. Таб открывается запросом списка аллергий — скелетон/пустое состояние по общим правилам (пустое состояние: призыв добавить первую аллергию, действие «+ Добавить аллергию» показывается всегда).

2. Список показывает аллергии карточками: аллерген, реакция (если заполнена, как заметка под названием), степень тяжести («Легкая»/«Средняя»/«Тяжёлая»). Для каждой аллергии имеется возможность открыть форму редактирования и удалить её.

3. «+ Добавить аллергию» / «редактировать» открывают форму: Аллерген (обязательное, ≤100), Реакция (опционально, ≤200, свободный текст — например, «кожная»), Когда выявлена (опционально, без ограничения диапазона), Степень реакции — переключатель из трёх вариантов «Легкая»/«Средняя»/«Тяжёлая» (обязательный, по умолчанию «Легкая» при создании), Заметка (опционально, ≤1000, multiline), блок прикрепления файлов (до 10).

4. «Сохранить» применяет результат оптимистично и сразу возвращает на таб «Аллергии», не дожидаясь ответа сервера (см. «Общие требования: Оптимистичные обновления (dataSource=network)»).

5. Удаление — оптимистичное, с окном отмены (см. там же, раздел «Оптимистичное удаление с окном отмены (Undo)»). Пока созданная запись не подтверждена сервером (временная карточка с индикацией «синхронизируется»), она доступна только для просмотра: открыть, отредактировать и удалить её нельзя (см. там же, раздел «Визуальная индикация фоновой синхронизации»).

## Бизнес-правила и валидация

Обязательные поля: «Аллерген», «Степень реакции».

При редактировании форма отправляет полный набор полей: очищенное необязательное поле («Реакция», «Когда выявлена», «Заметка») передаётся в `PATCH /allergies/{id}` пустой строкой `""` — так сервер очищает значение (см. «Аллергии — Backend»).

## Обработка ошибок

| Ситуация | Что делает система |
| --- | --- |
| Не заполнено обязательное поле | Форма не отправляется, сообщение под полем |
| Транзиентная ошибка сервера при сохранении (нет сети/таймаут/5xx) | Оптимистичное изменение остаётся применённым, запрос уходит в очередь фоновых повторов, карточка показывает индикатор «синхронизируется» (см. «Общие требования: Оптимистичные обновления», разделы «Классификация ошибок мутации», «Очередь фоновых мутаций и повторные попытки») |
| Постоянная ошибка сервера при сохранении (400/403/409) | Оптимистичное изменение откатывается, пользователю показывается сообщение об ошибке; введённые данные для повторной отправки не сохраняются (см. там же, «Обработка ошибок и откат») |
| Отложенный `DELETE` не доставлен — транзиентная ошибка | Запрос уходит в очередь фоновых повторов, аллергия остаётся удалённой из списка без отката (см. там же, «Оптимистичное удаление с окном отмены (Undo)») |
| Отложенный `DELETE` завершился постоянной ошибкой / повторы исчерпаны | Аллергия восстанавливается в списке, сообщение об ошибке с возможностью повторить удаление (см. там же) |
| Аллергия уже удалена на другом устройстве | Тихо убрать из списка / «уже удалено» |

## Хранение состояния и побочные эффекты

После создания/редактирования/удаления — инвалидация кэша списка аллергий питомца; этот кэш списка патчится синхронно и оптимистично (см. «Общие требования: Оптимистичные обновления (dataSource=network)»).
