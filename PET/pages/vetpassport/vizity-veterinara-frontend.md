## Назначение

Секция «Посещения ветеринара» таба «Медкарта»: список визитов питомца, экраны добавления/редактирования.

## Основной сценарий

1. Секция открывается запросом списка визитов — скелетон/пустое состояние по общим правилам.

2. Список показывает визиты карточками: причина визита, «{visit_date} · {clinic}» (без «·» и без клиники, если `clinic` не заполнена), заметка, иконки «редактировать»/«удалить».

3. «+ Добавить» / «редактировать» открывают форму: Дата посещения (обязательная, без ограничения диапазона), Причина визита (обязательное, ≤200), Клиника/врач (опционально, ≤200), Заметка (опционально, ≤1000, multiline), блок прикрепления файлов (до 10).

4. «Сохранить» применяет результат оптимистично и сразу возвращает на таб «Медкарта», не дожидаясь ответа сервера (см. «Общие требования: Оптимистичные обновления (dataSource=network)»).

5. Удаление — оптимистичное, с окном отмены (см. там же, раздел «Оптимистичное удаление с окном отмены (Undo)»).

## Бизнес-правила и валидация

Обязательные поля: «Дата посещения», «Причина визита».

## Обработка ошибок

| Ситуация | Что делает система |
| --- | --- |
| Не заполнено обязательное поле | Форма не отправляется, сообщение под полем |
| Транзиентная ошибка сервера при сохранении (нет сети/таймаут/5xx) | Оптимистичное изменение остаётся применённым, запрос уходит в очередь фоновых повторов, карточка показывает индикатор «синхронизируется» (см. «Общие требования: Оптимистичные обновления», разделы «Классификация ошибок мутации», «Очередь фоновых мутаций и повторные попытки») |
| Постоянная ошибка сервера при сохранении (400/403/409) | Оптимистичное изменение откатывается, форма становится черновиком, доступным повторно через приглушённую карточку (см. там же, «Черновики несохранённых операций») |
| Отложенный `DELETE` не доставлен — транзиентная ошибка | Запрос уходит в очередь фоновых повторов, визит остаётся удалённым из списка без отката (см. там же, «Оптимистичное удаление с окном отмены (Undo)») |
| Отложенный `DELETE` завершился постоянной ошибкой / повторы исчерпаны | Визит восстанавливается в списке, error-snackbar с действием «Повторить» (см. там же) |
| Визит уже удалён на другом устройстве | Тихо убрать из списка / «уже удалено» |

## Хранение состояния и побочные эффекты

После создания/редактирования/удаления — инвалидация кэша списка визитов питомца; этот кэш — первичный, патчится синхронно и оптимистично (см. «Общие требования: Оптимистичные обновления (dataSource=network)»).
