## Назначение

Таб «Вакцинации» экрана «Ветпаспорт»: блок «Ближайшая вакцинация» + список всех вакцинаций питомца, экраны добавления/редактирования вакцинации.

## Основной сценарий

1. Таб открывается запросом списка вакцинаций питомца. Пока запрос не завершён — скелетон списка (см. «Общие требования: UI-паттерны запросов»); если список пуст — пустое состояние с призывом добавить первую вакцинацию.

2. Система вычисляет **статус** каждой вакцинации по `next_date`, полностью на клиенте (backend статус не хранит и не возвращает, см. «Вакцинации — Backend»):
   * `next_date` отсутствует — статус не вычисляется, бейдж не показывается.
   * `next_date` раньше текущей календарной даты — **«Просрочена»**.
   * `next_date` наступает в течение 30 дней от текущей даты включительно — **«Скоро»**.
   * `next_date` позже, чем через 30 дней — **«Актуальна»**.

3. Блок «Ближайшая вакцинация» вверху таба показывает вакцинацию с ближайшей будущей/сегодняшней `next_date` среди всех вакцинаций питомца (минимальная `next_date >= сегодня`). Если ни у одной вакцинации нет `next_date >= сегодня` (включая случай, когда ни у одной вакцинации `next_date` вообще не задан), блок не отображается вовсе — карточки нет.

4. Список показывает все вакцинации карточками: название, дата введения, дата следующей (если есть), бейдж статуса (если вычислен, см. шаг 2), иконки «редактировать»/«удалить».

5. «Добавить вакцинацию» и иконка «редактировать» открывают форму (общую для обоих режимов, см. «Добавление питомца — Frontend» — тот же паттерн одной формы для create/edit с разным заголовком/текстом кнопки): Название вакцины (обязательное, ≤100 символов), Дата введения (обязательная, не позднее текущей даты — по аналогии с датой рождения питомца), Дата следующей вакцинации (опциональная, без ограничения диапазона — может быть в прошлом при внесении задним числом), чекбокс «Добавить событие на дату введения», чекбокс «Добавить событие на дату следующей вакцинации» (недоступен/скрыт, пока не заполнена «Дата следующей вакцинации»), при отметке любого из чекбоксов — общее на оба поле «Время события» (`HH:mm`, обязательное в этом случае, по умолчанию `09:00`), блок прикрепления файлов (до 10, изображения и документы — см. «Общие требования: Файлы сущностей»).

6. При редактировании форма предзаполняется текущими значениями; если у записи уже есть `administered_event_id`/`next_event_id`, соответствующий чекбокс изначально отмечен. Снятие отметки у чекбокса, под которым уже было создано событие, приведёт при сохранении к удалению этого события (см. «Вакцинации — Backend») — форма не показывает отдельного предупреждения об этом (в отличие от лекарств, где риск многократного пересоздания событий по расписанию оправдывает подтверждение, см. «Лекарства — Frontend») — здесь на кону не больше одного события за раз.

7. «Сохранить» блокирует повторное нажатие и показывает индикатор загрузки на время запроса (см. «Общие требования: UI-паттерны запросов»); после успеха — возврат на таб «Вакцинации» с инвалидацией кэша списка.

## Бизнес-правила и валидация

* Обязательные поля: «Название вакцины», «Дата введения». «Дата следующей вакцинации» — опциональна.

* «Дата введения» не может быть позднее текущей даты (валидация формы, зеркально серверу нет — сервер такой проверки не делает, см. «Вакцинации — Backend»; расхождение осознанное: клиент направляет пользователя к разумному вводу, но не блокирует внесение данных нестандартным путём на уровне API).

* «Время события» обязательно, если отмечен хотя бы один из двух чекбоксов «Добавить событие…».

## Обработка ошибок

| Ситуация | Что делает система |
| --- | --- |
| Не заполнено обязательное поле | Форма не отправляется, сообщение под полем |
| Ошибка сервера при сохранении | Snackbar/alert с сообщением об ошибке, форма не закрывается, данные не теряются |
| Вакцинация уже удалена на другом устройстве (404 при открытии формы редактирования/при сохранении) | Тихо убрать из списка / показать «уже удалено», без error-тоста (см. «Общие требования: Soft-delete», раздел «UX при гонках удаления») |

## Хранение состояния и побочные эффекты

После создания/редактирования/удаления вакцинации — инвалидация кэша списка вакцинаций питомца. Если операция создала/изменила/удалила связанное событие-напоминание — также инвалидация кэша календаря/списка событий питомца, чтобы напоминание сразу появилось/исчезло там.
